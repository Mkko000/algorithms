Quicksort (C. A. R. Hoare، 1960) هو غالبًا أكتر خوارزمية ترتيب متستخدمة في العالم. ليه؟ متوسطه 2N ln N مقارنة، الـ loop الداخلي بتاعه قصير بشكل مضحك، بيرتّب في المكان، وبيحب الكاش. وفي نفس الوقت عنده أسوأ حالة N² ممكن تقع فيها من غير ما تاخد بالك. الفصل كله عن الاتنين: إزاي تستغل سرعته، وإزاي تتجنب فخاخه.

هدف الدرس: تفهم الـ partitioning لدرجة إنك تكتبه من غير ما تبص، تعرف ليه المتوسط 2N ln N وليه الأسوأ N²، وتكتب نسخة غير ريكيرسف مضمون إن الـ stack فيها مايزيدش عن lg N.

7.1 الخوارزمية الأساسية

quicksort هو divide-and-conquer (الدرس 11) بس «الشغل» في القسمة مش في الدمج. الـ partition بيرتّب المصفوفة بحيث:

  1. عنصر a[i] (الـ pivot) بقى في مكانه النهائي.
  2. مفيش عنصر في a[l..i-1] أكبر منه.
  3. مفيش عنصر في a[i+1..r] أصغر منه.

وبعدين رتّب الجزئين ريكيرسف. مفيش دمج — لما الجزئين يترتبوا، الكل مترتب.

/* Program 7.1 */
void quicksort(Item a[], int l, int r)
  { int i;
    if (r <= l) return;
    i = partition(a, l, r);
    quicksort(a, l, i-1);
    quicksort(a, i+1, r); }

الـ partition (Program 7.2)

خد آخر عنصر v = a[r] كـ pivot. مؤشر i ماشي من الشمال لحد ما يلاقي عنصر مش أصغر من v، وj من اليمين لحد ما يلاقي عنصر مش أكبر. الاتنين دول في المكان الغلط — بدّلهم. كمّل لحد ما المؤشرين يتقابلوا، وبعدين حط الـ pivot مكان i.

int partition(Item a[], int l, int r)
  { int i = l-1, j = r; Item v = a[r];
    for (;;)
      { while (less(a[++i], v)) ;
        while (less(v, a[--j])) if (j == l) break;
        if (i >= j) break;
        exch(a[i], a[j]); }
    exch(a[i], a[r]);
    return i; }

تفاصيل صغيرة بس كل واحدة ليها سبب:

  • loop الـ i مش محتاج شرط حدود: الـ pivot نفسه في a[r] هيوقفه.
  • loop الـ j محتاج if (j == l) break لو الـ pivot أصغر عنصر.
  • الاتنين بيقفوا عند المساوي للـ pivot. شكلها تبديلات زيادة، بس هي اللي بتضمن إن ملف كله مفاتيح متساوية يتقسم في النص بدل ما يبقى N² (هنرجعلها في الدرس 18).

7.2 الأداء

الأسوأ (Property 7.1): حوالي N²/2

لو المصفوفة مترتبة أصلًا، الـ pivot (آخر عنصر) هو الأكبر. الـ partition بيشيل عنصر واحد بس كل مرة: N + (N−1) + … ≈ N²/2. ومش بس الوقت: عمق الريكيرشن N.

sorted  N=4000 (naive pivot): 8005998 compares, N^2/2 = 8000000

ودي مش حالة نادرة نظرية — الملفات المترتبة أو شبه المترتبة شائعة جدًا في الحياة.

المتوسط (Property 7.2): حوالي 2N ln N

لو المدخل عشوائي، كل عنصر عنده نفس الفرصة إنه يبقى الـ pivot. ده بيدّي recurrence:

C(N) = N + 1 + (1/N) Σ (C(k−1) + C(N−k)),   k = 1..N

وحلها (بالأسلوب بتاع الدرس 04) C(N) ≈ 2N ln N ≈ 1.39 N lg N. يعني بس 39% أكتر من الحالة المثالية اللي كل partition فيها بالظبط في النص.

random  N=100000: 2148169 compares, 2N ln N = 2302585

(القيمة الحقيقية أقل شوية من الصيغة لأن الصيغة الدقيقة فيها حدود سالبة من الدرجة N.)

الحل العملي للأسوألو مش عارف المدخل جاي منين: اخلط المصفوفة الأول، أو اختار الـ pivot عشوائي. ساعتها احتمال الـ N² بيبقى ضئيل لدرجة إنه أقل من احتمال إن الجهاز نفسه يضرب. والطريقة التانية — median-of-three — في الدرس الجاي.

7.3 حجم الـ stack

الريكيرشن بيستخدم stack. في الأسوأ عمقه N — يعني على مليون عنصر مترتب، الـ quicksort الساذج ممكن يعمل stack overflow قبل ما يخلص.

Program 7.3 بيشيل الريكيرشن ويستخدم stack صريح، وبيضيف حيلة واحدة ذكية: ادفع الجزء الأكبر الأول، والأصغر بعده — فالأصغر هو اللي يتعالج على طول.

#define push2(A, B)  push(B); push(A);
void quicksort(Item a[], int l, int r)
  { int i;
    stackinit(); push2(l, r);
    while (!stackempty())
      { l = pop(); r = pop();
        if (r <= l) continue;
        i = partition(a, l, r);
        if (i-l > r-i)
          { push2(l, i-1); push2(i+1, r); }
        else
          { push2(i+1, r); push2(l, i-1); } } }

Property 7.3: مع القاعدة دي، الـ stack أقل من lg N إدخال. السبب: كل إدخال فوق في الـ stack حجمه أقل من نص اللي تحته.

random        naive push order       max stack entries = 20
random        smaller subfile first  max stack entries = 9
1 2 .. N-1 0  naive push order       max stack entries = 20000
1 2 .. N-1 0  smaller subfile first  max stack entries = 2

شوف المدخل الأخير: الترتيب الساذج احتاج 20000 خانة. الذكي احتاج 2.
