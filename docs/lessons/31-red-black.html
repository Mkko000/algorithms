13.3 Top-Down 2-3-4 Trees

الفكرة: نسمح للعقدة إنها تشيل أكتر من مفتاح.

Definition 13.1: الـ 2-3-4 search tree يا إما فاضية، يا إما مكوّنة من تلات أنواع عقد: 2-node (مفتاح واحد ولينكين)، 3-node (مفتاحين وتلات لينكات: أصغر، بين الاتنين، أكبر)، و4-node (تلات مفاتيح وأربع لينكات).
Definition 13.2: الـ 2-3-4 tree المتوازنة هي اللي كل اللينكات الفاضية فيها على نفس المسافة من الجذر.

البحث سهل: في كل عقدة قارن بالمفاتيح اللي فيها واختار اللينك المناسب. الصعب هو الـ insert مع الحفاظ على التوازن الكامل.

الـ insert: الـ split في السكة

لو البحث وصل لورقة 2-node أو 3-node: حط المفتاح جواها (2 بقت 3، 3 بقت 4). سهل. بس لو الورقة 4-node؟ مفيش مكان. الحل: قسّمها — المفتاح اللي في النص يطلع للأب، والاتنين التانيين يبقوا 2-nodes. بس لو الأب كمان 4-node؟

الحيلة top-down: وإحنا نازلين في البحث، أي 4-node نقابلها نقسمها على طول. كده نضمن إن الأب عمره ما يبقى 4-node لما نيجي نقسم ابنه. ولو الجذر نفسه 4-node، نقسمه ونعمل جذر جديد — والشجرة تطول مستوى من فوق، فكل الأوراق تفضل على نفس العمق.

اتبع الرسمة: كل insert بيتكتب جنبه أي split حصل في السكة. لاحظ إن الشجرة عمرها ما بتطول غير لما الجذر يتقسم، وإن كل الأوراق دايمًا على نفس المستوى.

Property 13.6: البحث في 2-3-4 tree فيها N عقدة بيزور lg N + 1 عقدة على الأكتر.
Property 13.7: الـ insert في 2-3-4 tree فيها N عقدة بيحتاج أقل من lg N + 1 split في أسوأ حالة، والظاهر إنه بيحتاج أقل من split واحد في المتوسط.

13.4 Red-Black Trees

الفكرة: مثّل الـ 3-node والـ 4-node كـ BST صغيرة، و«لوّن» اللينكات الداخلية دي بالأحمر. اللينك الأحمر معناه «العقدتين دول في الحقيقة عقدة واحدة في الـ 2-3-4». واللينكات السودا هي لينكات الـ 2-3-4 الحقيقية.

  • 2-node = عقدة سودا عادية.
  • 3-node = عقدة سودا وولد أحمر (شمال أو يمين — الاتنين ينفعوا).
  • 4-node = عقدة سودا وولدين أحمر.
Definition 13.3: الـ red-black BST هو BST كل عقدة فيه حمرا أو سودا، بشرط إن مفيش عقدتين حمر ورا بعض على أي مسار.
Definition 13.4: الـ red-black BST المتوازن هو اللي كل المسارات من الجذر لأي لينك فاضي فيها نفس عدد العقد السودا.

(في الكود، اللون بيتخزّن في العقدة نفسها ومعناه لون اللينك اللي جاي من الأب.) والجميل: البحث هو بحث BST عادي حرفيًا — بيتجاهل الألوان خالص. يعني أسرع من أي شجرة متوازنة تانية في البحث.

الـ insert (Program 13.6)

نفس الـ top-down 2-3-4، بس بالألوان والـ rotations:

  1. وإحنا نازلين: عقدة ولادها الاتنين حمر = 4-node. اقلب الألوان: الولدين يبقوا سود، والعقدة حمرا (المفتاح اللي في النص «طلع» للأب). ده الـ split.
  2. العقدة الجديدة دايمًا حمرا (بتنضم لعقدة 2-3-4 موجودة).
  3. وإحنا طالعين: لو الـ flip أو العقدة الجديدة عملوا أحمرين ورا بعض، صلّحهم بـ rotation (لو في نفس الاتجاه) أو اتنين (لو zig-zag).
link RBinsert(link h, Item item, int sw)
  { Key v = key(item);
    if (h == z) return NEW(item, z, z, 1, 1);
    if ((hl->red) && (hr->red))
      { h->red = 1; hl->red = 0; hr->red = 0; }
    if (less(v, key(h->item)))
      {
        hl = RBinsert(hl, item, 0);
        if (h->red && hl->red && sw) h = rotR(h);
        if (hl->red && hll->red)
          { h = rotR(h); h->red = 0; hr->red = 1; }
      }
    else
      {
        hr = RBinsert(hr, item, 1);
        if (h->red && hr->red && !sw) h = rotL(h);
        if (hr->red && hrr->red)
          { h = rotL(h); h->red = 0; hl->red = 1; }
      }
    fixN(h); return h; }
void STinsert(Item item)
  { head = RBinsert(head, item, 0); head->red = 0; }

الـ sw بيقول إحنا جينا للعقدة دي من شمال أبوها (0) ولا يمين (1). لو العقدة حمرا وولدها اللي رجع منه أحمر والاتجاه بيلف، دي حالة zig-zag: أول rotation عندها عشان تبقى على خط مستقيم، وبعدين الأب هيعمل التانية.

ودلوقتي الحقيقة كاملة: ده تتبّع Program 13.6 على ASEARCHINGEXAMPLE، كل خطوة مكتوب فيها الـ flips والـ rotations اللي حصلت بالظبط (من محاكاة حرفية للكود):

inorder (* = red): A A* A* C E E E* G* H I L* M N* P R S X*
count = 17, search X -> hit, search Z -> miss

قارن آخر خطوة في الـ stepper بالسطر ده: نفس الألوان بالظبط (* = أحمر). ولو «لزقت» كل عقدة حمرا في أبوها، هترجع لك 2-3-4 tree متوازنة — مش بالضرورة نفس الشجرة اللي فوق بالظبط، لأن الـ rotations في Program 13.6 بتختار أحيانًا تمثيل مختلف لنفس المفاتيح، بس دايمًا 2-3-4 متوازنة.

الضمانات

Property 13.8: البحث في red-black tree فيها N عقدة بيحتاج أقل من 2 lg N + 2 مقارنة.

ليه؟ عدد العقد السودا على أي مسار ≤ lg N + 1 (ده ارتفاع الـ 2-3-4)، ومفيش أحمرين ورا بعض، فأطول مسار على الأكتر ضعفه.

الأرقام بتقول كل حاجة: حتى بالمفاتيح المترتبة، الارتفاع 25 (أقل كتير من الحد 35)، ومتوسط البحث حوالي lg N (التجربة بتدّي 0.96 lg N تقريبًا، وده متوافق مع «حوالي lg N» — يعني الشجرة شبه مثالية). والبرنامج بيتأكد من التعريفين 13.3 و13.4 (مفيش أحمرين، والـ black height متساوي) بعد مئة ألف insert.

ليه red-black هو الاختيار الأول؟البحث = BST search بالظبط من غير أي overhead. الـ insert بيبص على بتّين في كل عقدة وأحيانًا rotation. والذاكرة: بت واحد زيادة لكل عقدة. والضمان: worst case 2 lg N. الـ delete أصعب (الكتاب سايبه تمرين)، وفيه نسخ أبسط في الكتابة زي الـ left-leaning red-black tree اللي سادجوك نفسه نشرها بعد الكتاب بسنين، بس الفكرة الأساسية هي هي.

في top-down 2-3-4، ليه بنقسم أي 4-node وإحنا نازلين؟

لو الأب كان 4-node، الـ split هيطلّع مفتاح ليه ومش هيبقى فيه مكان، وهنحتاج نطلع لفوق تاني. الـ top-down بيمنع ده من الأول.

إمتى الـ 2-3-4 tree بتطول مستوى؟

الشجرة بتكبر من فوق مش من تحت. عشان كده كل الأوراق بتفضل على نفس العمق دايمًا (Definition 13.2).

عقدة سودا ولادها الاتنين حمر. في الـ 2-3-4 دي إيه؟ وProgram 13.6 بيعمل فيها إيه وهو نازل؟

تلات مفاتيح ملزوقين بلينكين حمر = 4-node. الـ color flip = الـ split: الولدين يبقوا 2-nodes منفصلين والأب «يطلع» للعقدة اللي فوق.
