Quicksort هو الحصان الأسود: متوسط O(N log N)، ثوابت صغيرة، بيحب الكاش، وعلى أغلب المدخلات بيكتسح. وفي نفس الوقت أسوأ حالة O(N²) لو أنت غافل. الفصل السابع كلّه عن إنك متبقاش غافل.

هدف الدرس: تفهم الـ partitioning بعمق، التحسينات (median-of-three، cutoff)، والـ 3-way لما المفاتيح تتكرّر.

الفكرة في جملة

اختار pivot، قسّم المصفوفة: أصغر منه على الشمال، أكبر على اليمين، هو في مكانه النهائي. بعدين كرّر على الجهتين. كل عنصر بيتقف في مكانه مرة واحدة — عشان كده في الآخر كله مترتّب.

int partition(Item a[], int l, int r) {
    int i = l - 1, j = r; Item v = a[r];
    for (;;) {
        while (less(a[++i], v)) ;
        while (less(v, a[--j])) if (j == l) break;
        if (i >= j) break;
        exch(a[i], a[j]);
    }
    exch(a[i], a[r]);
    return i;
}
الغلطة الكلاسيكيةتنسى تضمن إن عنصر واحد على الأقل يدخل مكانه، فتدخل ريكيرشن لا نهائي لما الـ pivot يبقى أصغر أو أكبر عنصر. كود سادجوك بيحمي بـ if (j == l) break وبتبادل الـ pivot في الآخر.

تحسينات عملية (Program 7.4)

  • Median-of-three: pivot = وسيط أول ووسط وآخر عنصر. بيقلّل فرص القسمة الوحشة.
  • Cutoff to insertion: تحت حجم ~10، سيّب الملف، وفي الآخر insertion بيلمّع الكل. التفاصيل الصغيرة أغلى من الـ partition.

تلات طريق (3-way) — Dijkstra

لما عندك مفاتيح مكررة كتير، الـ partition العادي غبي: بيسيب المتساوي يتقسم تاني. الـ 3-way بيقسم لـ < و = و >، والمتساوي خلاص خلص. على بيانات فيها تكرار، الفرق درامي.

Quickselect

عايز الوسيط بس؟ نفس الـ partition، بس ادخل الجهة اللي فيها k. متوسط O(N). أذكى بكتير من ترتيب الكل.

جرّب بنفسكفي محاكي الترتيب (الدرس السابق) اختار Quicksort وشوف الـ pivot وهو بيتقف، والجناحين بيتقلّصوا. العين بتفهم أسرع من المعادلات.
