تمارين محلولة · الفصل 16 (External Searching) · تمارين 16.1–16.39

في الفصل 16 الحسبة كلها بتتغير. المقارنات بقت ببلاش تقريبًا، واللي بيكلّف بجد هو قراية صفحة من الديسك (probe). فالسؤال بقى: كام صفحة لازم نقرا عشان نلاقي مفتاح وسط مليار؟ والإجابة في الفصل كله رقم صغير جدًا، 2 أو 3. التمارين هنا ليها تلات أشكال: «احسب log_M N وشوف قد إيه صغير»، و«ارسم الـ B tree أو الـ extendible hash table بعد الـ inserts دي»، و«حاكي نمو الصفحات وشوف هتبقى مليانة قد إيه».

هدف الدرس: تحس بحجم log_M N، وتبني ISAM وB tree بالإيد وتعرف إمتى وفين بيحصل الـ split، وتفرّق بين الـ B tree اللي في الكتاب (index) وشجرة 3-4-5-6 المجردة، وتبني extendible hash table وتفهم الدليل بيتضاعف ليه، وتقيس الصفحات بتتملي قد إيه في B tree وB* وextendible hashing.
المفاتيح دي octalالمفاتيح اللي زي 516 و177 و562 في أمثلة الكتاب أرقام octal من 3 خانات، يعني كل مفتاح 9 بت (3 بت لكل خانة). 562 = 101 110 010. في الـ B tree ده مش فارق، لأننا بنقارن بس والترتيب واحد. لكن في الـ extendible hashing بنبص على أول بتات المفتاح، فلازم تكتب كل مفتاح بالـ binary الأول.

تمرين 16.1، 16.21 و16.12: log_M N صغير قد إيه؟

نص التمرين: (16.1) اعمل جدول بقيم log_M N لـ M = 10 و100 و1000، وN = 10³ و10⁴ و10⁵ و10⁶. (16.21) اعمل جدول بالفرق بين log₉₉₉ N وlog₁₀₀₀ N لنفس قيم N. (16.12) افترض إن عندنا شجرة من 3 مستويات، ونقدر نشيل a links في الميموري، وفي صفحات الـ nodes الداخلية من b لـ 2b link، وفي الصفحات الخارجية من c لـ 2c item. إيه أقصى عدد items تقدر الشجرة دي تشيله، كـ function في a وb وc؟
بنفكّر إزايالصفحة اللي فيها M entry بتقسم مساحة البحث M حتة مرة واحدة. فبعد h صفحة نقدر نفرّق بين M^h مفتاح، يعني h = log_M N. ولـ 16.21: log₉₉₉ N − log₁₀₀₀ N = ln N × (1/ln 999 − 1/ln 1000)، ده رقم صغير جدًا. ولـ 16.12: أقصى عدد بيحصل لما كل الصفحات تبقى مليانة لآخرها.

تمرين 16.11، 16.13 و16.16: محاكاة نمو الصفحات وB*

نص التمرين: (16.11) اكتب برنامج يحسب متوسط عدد الصفحات الخارجية لـ B tree من order M اتبنى من N insert عشوائي، باستعمال العملية الاحتمالية اللي بعد Property 16.1، لـ M = 10 و100 و1000 وN = 10³ لحد 10⁶. (16.13) فكّر في الـ sibling split (أو B* tree): لما node يجي وقت إنها تتقسم، بنضمها مع جارتها. لو الجارة فيها k entry وk < M − 1، نوزّع الـ items عليهم بحيث كل واحدة تاخد حوالي (M + k)/2. غير كده، نعمل node جديدة ونوزّع على التلاتة كل واحدة حوالي 2M/3. اكتب حدود عدد الـ probes في البحث أو الـ insert في B* tree، وقارنها بالـ B tree. (16.16) اعمل محاكاة احتمالية تحسب متوسط عدد الصفحات مع الـ sibling split لنفس M وN.
بنفكّر إزايمش محتاجين نبني الشجرة خالص. اللي يهمنا الصفحات الخارجية وكل واحدة فيها كام. والمفتاح العشوائي بيقع في صفحة باحتمال على قد حجمها (كل فراغ بين مفتاحين ليه نفس الفرصة)، وده الـ Markov chain بتاع Yao. والحيلة: نختار صفحة عشوائي، ونقبلها باحتمال size/M (rejection sampling)، كأننا اخترنا item عشوائي. ولـ B* محتاجين الجيران بجد، فبنحط الصفحات في linked list بالترتيب. ولـ 16.13: في B tree كل node جوه فيها من M/2 لـ M link، فالارتفاع بين log_M N وlog_(M/2) N. وفي B* كل node فيها على الأقل 2M/3، فالحد الأعلى بيبقى log_(2M/3) N.
