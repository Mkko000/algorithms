كل هياكل البحث اللي فاتت افترضت الذاكرة سريعة ومتجانسة. لما البيانات على قرص أو شبكة، تكلفة قراءة صفحة واحدة آلاف المرات تكلفة مقارنة في RAM. هنا يدخل الـ B-tree.

هدف الدرس: تفهم ليه نوسّع العقد، إيه هو الـ B-tree، وإزاي الـ split بيحافظ على التوازن.

الفكرة

خلّي كل عقدة تمسك تلاتة / أربعة / … / مئات المفاتيح — قد صفحة القرص. شجرة قليلة الارتفاع جدًا: بـ M=1024 و ملايين المفاتيح، الارتفاع 2 أو 3. يعني 2–3 قراءات قرص للبحث.

#define M 4   /* order: max M-1 keys per node */
struct node {
    int m;            /* عدد المفاتيح النشطة */
    int key[M];
    link child[M+1];
    int leaf;
};

الإدخال والانقسام

لو الصفحة ممتلئة، انقسم لنصّين، وابعت المفتاح الأوسط للأب. لو الأب كمان ممتلئ، الانقسام يتصعّد — وأحيانًا الجذر بينقسم ويزيد ارتفاع الشجرة بواحد. كده الشجرة دايمًا متوازنة من ارتفاعها.

في قواعد البيانات:B+ trees (قريب جدًا) هي عمود فقري للفهارس. مش صدفة — مصمّمة بالظبط لعالم الصفحات.
الفرق عن Red-Blackالاتنين متوازنين. Red-Black للذاكرة الداخلية (M=2 منطقيًا). B-tree للخارجية (M كبير). نفس الروح: متخليش المسارات تطول.

ليه M كبير في B-tree؟

تكلفة القرص ≫ تكلفة المقارنة. قلل عدد القراءات.

لما عقدة تمتلي في الإدخال؟

الـ split هو قلب الحفاظ على التوازن في B-tree.
