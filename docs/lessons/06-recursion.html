في ناس بتخاف من الريكيرشن كأنه سحر أسود. الحقيقة: هو ترجمة مباشرة لتعريف رياضي. المشكلة لما التعريف يتشعّب من غير مذكرة — ساعتها بتفجّر الزمن.

هدف الدرس: تتقن الريكيرشن الصحي، تفهم divide-and-conquer، تشوف فخ Fibonacci، وتعدّي على DFS/BFS.

شكل الريكيرشن الصح

كل دالة ريكيرسف لازم: (1) حالة قاعدة بتقف، (2) حالة بتصغّر المشكلة نحو القاعدة. من غير الاتنين: يا loop لا نهائي يا إجابة غلط.

int factorial(int N) {
    return (N == 0) ? 1 : N * factorial(N - 1);
}

Fibonacci: درس في الإذلال

النسخة الساذجة بتشعّب لاستدعاءين كل مرة. الشجرة حجمها أسي. fib(40) يتلكّع على جهازك. الحل؟ Dynamic programming: احسب كل قيمة مرة واحدة.

قاعدة سادجوكلو لقيت نفس الـ subproblem بتتحل مرّات، خزن الناتج. دي فكرة الـ DP كلها في جملة.

Divide and Conquer

قسّم لمشكلتين أصغر، حلّ، ادمج. أبراج هانوي، ولاحقًا mergesort و quicksort — نفس الهيكل.

الشجر والجرافات

Preorder / inorder / postorder: الفرق بس امتى تزور الجذر. على الجراف: DFS = ريكيرشن أو stack. BFS = queue، وبيدّي أقصر مسار بعدد الأضلاع.

خلي بالكنسيان علامة visited في DFS على جراف فيه دورات = ستاك بيفيض. على الشجر مفيش دورات فبتنجو بالحظ — على الجراف لأ.

ليه fib الريكيرسف الساذج بطيء؟

عدد الاستدعاءات بينمو كـ Fibonacci نفسه تقريبًا. الـ DP بيخلّيها خطية.

BFS بيستخدم أنهي هيكل؟

FIFO بيضمن إن عقد المستوى k تتعالج قبل المستوى k+1.

inorder على BST بيطلع المفاتيح إزاي؟

شمال → جذر → يمين مع خاصية الـ BST = ترتيب.

أبراج هانوي لـ N قرص محتاجة كام نقلة؟

T(N) = 2*T(N-1) + 1 والحل 2^N - 1.
