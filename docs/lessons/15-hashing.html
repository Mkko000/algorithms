الشجر حلوة لما تحتاج ترتيب ومدى. لو عايز «جب لي المفتاح ده» بأقصى سرعة متوسطة، الـ hashing بيلعب في ملعب تاني: اقذف المفتاح في مصفوفة بحساب، وخلاص.

هدف الدرس: تفهم دالة الهاش، separate chaining، linear probing، والـ load factor.

دالة الهاش

تحوّل مفتاح → عدد في 0..M-1. الهدف: يتوزّع كالعشوائي. للنصوص، سادجوك بيستخدم Horner مع أساس 127:

int hash(char *v, int M) {
    int h = 0, a = 127;
    for (; *v != '\0'; v++)
        h = (a*h + *v) % M;
    return h;
}

ليه 127 مش 128؟ عشان تتجنّب تشوّهات لما M قوة 2. وفي نسخة universal بتغيّر المعاملات شبه عشوائي (Program 14.2).

Separate Chaining

كل خانة في الجدول راس قائمة. اصطدام؟ ادخل في القايمة. اضبط M ≈ N/5 عشان القوائم تفضل قصيرة. بحث/إدخال متوسط O(N/M) ≈ ثابت.

Linear Probing

مفيش قوائم: لو الخانة مشغولة، جرّب اللي بعدها (mod M). بسيط والكاش بيحبّه. بس لما الجدول يقرب يمتلي، الكلسترز بتطول والأداء يقع. عبّي أقل من النص (M ≈ 2N).

الحذف في linear probingمش مسح الخانة وخلاص — هتكسر سلسلة البحث. يا تعدّم (tombstone) يا تعيد إدراج السلسلة اللي بعدها (Program 14.5). خلي بالك قبل ما تنفّذ delete متعجّل.
Hash ضد BSTهاش: أسرع متوسط، مفيش ترتيب. BST/شجر: ترتيب، مدى، عمليات غنية، ضمانات. اختار على احتياجك مش على العادة.

هدف دالة الهاش الجيدة؟

كل ما التوزيع أقرب للعشوائي، القوائم/الـ probes أقصر.

Load factor عالي في linear probing يعمل إيه؟

بعد ~70% امتلا، الزمن بيزيد بحِدّة. سادجوك بينصح بالنص.

Separate chaining يحل الاصطدام إزاي؟

القائمة محلية؛ باقي الجدول مش بيتأثر.

هاش ولا Red-Black لو محتاج تطبع المفاتيح مرتّبة؟

الهاش ما بيدّاش ترتيب. الشجر بيدك inorder مجانًا.
