الـ trie فيه عيبين: عقد one-way كتير (1.44N عقدة داخلية بدل N)، ونوعين عقد مختلفين (داخلية وأوراق) بيعقّدوا الكود. Patricia (اسمها اختصار «Practical Algorithm To Retrieve Information Coded In Alphanumeric»، وMorrison اخترعها سنة 1968) بتحل الاتنين مرة واحدة بفكرة جميلة: N عقدة بالظبط لـ N مفتاح، كل عقدة فيها مفتاح ورقم البت اللي بتتفرّع عليه.

هدف الدرس: تفهم إزاي patricia بتتخلّص من الـ one-way branching بإنها تخزّن رقم البت، وإزاي اللينكات «اللي بترجع لفوق» بتلعب دور الأوراق، وتكتب search وinsert وsort، وتقارن DST وtrie وpatricia.

15.3 Patricia Tries

الفكرة الأولى: اقفز على البتات اللي مالهاش لازمة

في الـ trie، العقدة الـ one-way معناها «كل المفاتيح هنا ليها نفس البت ده». يبقى ليه نسأل عليه أصلًا؟ خلّي كل عقدة تخزّن رقم البت اللي فعلًا بيفرّق، ونقفز على الباقي. كده كل عقدة داخلية ليها ولدين دايمًا، فعددهم N − 1.

الفكرة التانية: مفيش أوراق

بدل N−1 عقدة داخلية + N ورقة، حط كل مفتاح في عقدة داخلية (فيه N مفتاح وN عقدة لو ضفنا header). والأوراق؟ اللينكات اللي كانت بتشاور على أوراق بقت بتشاور لفوق، على العقدة اللي فيها المفتاح ده. إزاي نعرف إن اللينك «لفوق»؟ رقم البت في العقدة اللي رحنالها أصغر من أو يساوي رقم البت في العقدة اللي جينا منها (لأن الأرقام بتزيد واحنا نازلين).

Item searchR(link h, Key v, int w)
  {
    if (h->bit <= w) return h->item;
    if (digit(v, h->bit) == 0)
         return searchR(h->l, v, h->bit);
    else return searchR(h->r, v, h->bit);
  }
Item STsearch(Key v)
  { Item t = searchR(head->l, v, -1);
    return eq(v, key(t)) ? t : NULLitem;
  }

(Program 15.4.) لاحظ: بنبص على البتات بس طول السكة، ولما نلف لفوق، نقارن المفتاح مرة واحدة بالكامل. والـ header عقدة فيها مفتاح كله أصفار وبت رقمه −1.

اقرا الجدول مع الشجرة: عشان تدوّر على N (01110)، الجذر S بيبص على بت 0 (=0) فشمال لـ H، اللي بيبص على بت 1 (=1) فيمين لـ N، اللي بيبص على بت 2 (=1) فيمين… لـ M (بت 3 = 1) → يمين M = لينك لفوق لـ N. قارن: N = N ✓. أربع بتات ومقارنة واحدة.

الإضافة (Program 15.5)

  1. ابحث عن المفتاح الجديد. هتوصل لمفتاح t (عن طريق لينك لفوق).
  2. لو t هو هو، مفيش حاجة تتعمل. وإلا: لاقي أول بت i المفتاح الجديد بيختلف فيه عن t.
  3. ابحث تاني من الأول، بس اقف قبل أي عقدة رقمها ≥ i (أو قبل لينك لفوق).
  4. حط عقدة جديدة هناك فيها المفتاح الجديد وبيت i: لينك منها بيشاور على نفسها (لفوق!) في اتجاه البت بتاع المفتاح الجديد، واللينك التاني على اللي كان موجود في المكان ده.
link insertR(link h, Item item, int w, link p)
  { link x; Key v = key(item);
    if ((h->bit >= w) || (h->bit <= p->bit))
      {
        x = NEW(item); x->bit = w;
        x->l = digit(v, x->bit) ? h : x;
        x->r = digit(v, x->bit) ? x : h;
        return x;
      }
    if (digit(v, h->bit) == 0)
         h->l = insertR(h->l, item, w, h);
    else h->r = insertR(h->r, item, w, h);
    return h; }
void STinsert(Item item)
  { int i;
    Key v = key(item);
    Key t = key(searchR(head->l, v, -1));
    if (v == t) return;
    for (i = 0; digit(v, i) == digit(t, i); i++) ;
    head->l = insertR(head->l, item, i, head); }

ليه البحث الأول كافي عشان نعرف البت i؟ لأن المفتاح t اللي وصلنا له بيشترك مع المفتاح الجديد في كل البتات اللي اتفحصت في السكة — فأول اختلاف بينهم هو أول بت «محدش سأل عليه» وبيفرّق.

الـ sort (Program 15.6)

الـ inorder العادي بيلف على الشجرة؛ بس في patricia، المفاتيح بتتطبع لما نمشي في لينك لفوق (ده مكان «الورقة»). والنتيجة مترتبة، زي الـ trie:

void sortR(link h, void (*visit)(Item), int w)
  {
    if (h->bit <= w) { visit(h->item); return; }
    sortR(h->l, visit, h->bit);
    sortR(h->r, visit, h->bit);
  }
