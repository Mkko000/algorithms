تمرين 2.5: إمتى 10 N lg N > 2N²؟

نص التمرين: لأنهي قيم N يكون 10 N lg N أكبر من 2N²؟
بنفكّر إزاياقسم الطرفين على 2N (N موجب): المتباينة تبقى 5 lg N > N. على الشمال دالة بتكبر ببطء، وعلى اليمين خط مستقيم. فأكيد في الآخر N هتكسب. يبقى السؤال: فين نقطة التقاطع؟ جرّب قوى 2: N = 16 تدّي 20 > 16 ✓، وN = 32 تدّي 25 < 32 ✗. يعني التقاطع بين 16 و32، وبعد كده نضيّق بالتجربة.
الحل

5 lg 22 = 22.3 > 22 ✓ و5 lg 23 = 22.6 < 23 ✗. وعند N = 1، الطرف الشمال صفر. فالإجابة: 2 ≤ N ≤ 22.

2.5  10 N lg N > 2 N^2  for  2 <= N <= 22

الدرس هنا: الخوارزمية اللي تكلفتها N lg N، حتى لو الثابت بتاعها أكبر 5 مرات، بتكسب الـ N² من أول N = 23. يعني الثوابت بتفرق في المسائل الصغيرة بس.

تمرين 2.6: N^{3/2} بين N(lg N)²/2 و2N(lg N)²

نص التمرين: لأنهي قيم N يكون N^{3/2} بين N(lg N)²/2 و2N(lg N)²؟
بنفكّر إزاياقسم على N: السؤال يبقى إمتى √N بين (lg N)²/2 و2(lg N)². الاتنين بيكبروا، بس بمعدّلات مختلفة جدًا: في الأول الـ (lg N)² بيكبر أسرع، وبعد كده √N بيسبقه. فممكن يطلع إن الإجابة مش فترة واحدة. ماتفترضش إنها فترة واحدة، واكتب برنامج يمسح.
الحل 
2.6  N^1.5 between N(lgN)^2/2 and 2N(lgN)^2 for N in: [2..3] [6381..519978]

فترتين! N = 2 و3 بالصدفة (الأرقام صغيرة). بعد كده من 4 لـ 6380 الـ √N أصغر من الحد الأدنى، ومن 6381 لحوالي نص مليون بيبقى جوه، وبعد كده بيعدّي الحد الأعلى. والمغزى العملي: خوارزمية N^{3/2} (زي shellsort بـ increments معيّنة، الفصل 6) و«N (lg N)²» ممكن يبقوا متقاربين جدًا في المدى اللي بنشتغل فيه. ده بالظبط اللي سادجوك بيقوله لما بيتكلم عن صعوبة التفرقة بين الدوال دي بالتجربة.

تمرين 2.7: 2N HN − N مقابل N lg N + 10N

نص التمرين: لأنهي قيم N يكون 2N HN − N < N lg N + 10N؟
بنفكّر إزاياقسم على N: 2HN − 1 < lg N + 10. واستخدم HN ≈ ln N + γ (γ ≈ 0.577). يبقى 2 ln N + 0.154 < 1.443 ln N + 10، يعني 0.557 ln N < 9.85، يعني ln N < 17.7، يعني N < e^{17.7} ≈ 4.8×10⁷. (ده الفرق بين عدد مقارنات quicksort، 2N ln N، والـ N lg N. هتقابله في الفصل 7.)
الحل

تقريبًا لكل N لحد حوالي 4.7×10⁷، وبعد كده المتباينة بتنقلب.

2.7  2N H_N - N < N lg N + 10N  holds up to N ~ 47013693 (about 4.8e7)

(البرنامج بيمشي بخطوات 0.1% بعد الألف، فالرقم دقيق للـ 0.1%.) والحسبة اليدوية والبرنامج متفقين.

تمرين 2.8 و2.9: لوغاريتمات

نص التمرين: (2.8) إيه أصغر N يخلّي log₁₀ log₁₀ N > 8؟ (2.9) أثبت إن ⌊lg N⌋ + 1 هو عدد البتات اللازمة لكتابة N بالـ binary.
بنفكّر إزايفي 2.8 فك اللوغاريتم مرتين: log₁₀ N > 10⁸، يعني N > 10^{10⁸}. وفي 2.9: عدد بتاته b يعني إنه بين أصغر وأكبر رقم بـ b بت، يعني 2^{b−1} ≤ N < 2^b. خد lg للطرفين.
الحل

2.8: أصغر N هو 10^{100000000} + 1: رقم فيه 100 مليون خانة! يعني log log N عمليًا ثابت، أقل من 8 لأي حاجة ممكن تقابلها في حياتك.

2.9: لو N محتاج b بت بالظبط (البت الأعلى 1)، يبقى 2^{b−1} ≤ N < 2^b. وبالـ lg: b−1 ≤ lg N < b، يعني ⌊lg N⌋ = b−1، يعني b = ⌊lg N⌋ + 1. ∎ والبرنامج اتأكّد من ده لكل N أقل من 5 مليون:

تمرين 2.12 و2.13: HN و⌈lg lg N⌉

نص التمرين: (2.12) اكتب دالة C تحسب HN باستخدام دالة log من الـ math library. (2.13) اكتب دالة C كفؤة تحسب ⌈lg lg N⌉ من غير أي library function.
بنفكّر إزايفي 2.12: ماتجمعش N كسر (ده O(N)). استخدم التقريب HN = ln N + γ + 1/(2N) − 1/(12N²) + … (Table 2.3 في الكتاب فيها أول حدّين). وفي 2.13: ⌈lg x⌉ هو أصغر k يخلّي 2^k ≥ x، ودي تتحسب بـ shifts. وبعدين طبّقها مرتين: ⌈lg ⌈lg N⌉⌉ = ⌈lg lg N⌉. (ليه ده صح؟ لأن ⌈lg y⌉ بيعتمد بس على أصغر قوة 2 ≥ y، والسقف مش بيعدّي قوة 2.)
الحل 
double harmonic(double n)
  { return log(n) + 0.57721566490153286 + 1/(2*n) - 1/(12*n*n); }

int ceil_lg(unsigned long long x)   /* smallest k with 2^k >= x */
  { int k = 0; unsigned long long p = 1;
    while (p < x) { p <<= 1; k++; }
    return k; }
int ceil_lglg(unsigned long long n) { return ceil_lg(ceil_lg(n)); }
2.12 H_N via log:   N=10 2.928967 (exact 2.928968)   N=1e6 14.392726723 (exact 14.392726723)
2.13 ceil(lg lg N): 2->0 4->1 5->2 16->2 17->3 256->3 65536->4 65537->5 1000000->5 4294967296->5

التقريب مضبوط لـ 6 أرقام حتى عند N = 10. ولاحظ إن ⌈lg lg N⌉ بيقفز عند 2^{2^k}+1 بالظبط (5، 17، 257، 65537).

تمرين 2.14: كام رقم في مليون factorial؟

نص التمرين: كام خانة في التمثيل العشري لـ 1,000,000!؟
بنفكّر إزايعدد خانات x هو ⌊log₁₀ x⌋ + 1 (نفس فكرة 2.9 بس بالعشري). وlog₁₀ N! = Σ log₁₀ k. أو استخدم Stirling: ln N! ≈ N ln N − N + ½ ln(2πN).
الحل

log₁₀(10⁶!) ≈ 5565708.917، يعني 5,565,709 خانة. والجمع المباشر وStirling متفقين لحد 4 أرقام عشرية:

2.14 1000000! has 5565709 decimal digits (log10 = 5565708.9172); Stirling: 5565708.9172

ودي هتهمّك في الفصل 8: lg N! ≈ N lg N − 1.44N هو الحد الأدنى لعدد المقارنات لأي sort.

تمرين 2.20: O(1) هي نفسها O(2)

نص التمرين: أثبت إن O(1) هي نفسها O(2).
بنفكّر إزايO(f) مش رقم. دي مجموعة دوال: g ∈ O(f) لو فيه ثابت c₀ وN₀ بحيث |g(N)| < c₀ f(N) لكل N > N₀. يبقى عايز تثبت إن المجموعتين فيهم نفس الدوال، يعني كل مجموعة جوه التانية.
الحل

لو g ∈ O(1): |g| < c₀·1 = (c₀/2)·2، فـ g ∈ O(2) بالثابت c₀/2. ولو g ∈ O(2): |g| < c₀·2 = (2c₀)·1، فـ g ∈ O(1) بالثابت 2c₀. ∎ والفكرة العامة: O(cf) = O(f) لأي ثابت c > 0، والثابت «بيتبلع» جوه c₀. وده بالظبط سبب إننا بنكتب O(N lg N) من غير ما نهتم بأساس اللوغاريتم.

تمرين 2.48 و2.49: احتمال التطابق، والـ driver
