insertion sort عنده عيب واحد قاتل: العنصر بيتحرك خطوة واحدة كل مرة. لو أصغر عنصر في آخر المصفوفة، هيمشي N خطوة. Donald Shell سنة 1959 قال: طب ما نخلّيه يقفز؟ والنتيجة خوارزمية بسيطة جدًا، سريعة جدًا، ولسه — بعد 60 سنة — تحليلها الكامل لغز.

هدف الدرس: تفهم shellsort ودور متتابعة الزيادات، ترتّب أي نوع بيانات بنفس الكود، ترتّب سجلات ضخمة من غير ما تحرّكها (فهارس ومؤشرات)، ترتّب قوائم مترابطة، وترتّب في زمن خطي لما المفاتيح صغيرة.

6.6 Shellsort (Program 6.5)

h-sorted = كل عنصر مترتب بالنسبة للعنصر اللي بعده بـ h خانة. يعني المصفوفة h متتابعة متداخلة، كل واحدة مترتبة. Shellsort: اعمل h-sort بـ h كبير (العناصر بتقفز مسافات كبيرة)، بعدين h أصغر، لحد h = 1 (insertion sort عادي — بس على مصفوفة شبه مترتبة، فسريع).

void shellsort(Item a[], int l, int r)
  { int i, j, h;
    for (h = 1; h <= (r-l)/9; h = 3*h+1) ;
    for ( ; h > 0; h /= 3)
      for (i = l+h; i <= r; i++)
        { int j = i; Item v = a[i];
          while (j >= l+h && less(v, a[j-h]))
            { a[j] = a[j-h]; j -= h; }
          a[j] = v; } }

ده insertion sort بالظبط بس 1 بقت h. والمتتابعة 1، 4، 13، 40، 121، … (h = 3h+1) من Knuth.

لو كل سجل 1KB، تبديل اتنين = نسخ 3KB. ليه نحرّكهم أصلًا؟

  • Index sort: مصفوفة a[] فيها 0..N−1، ورتّبها بمقارنة data[a[i]]. النتيجة: data[a[0]] هو الأصغر. السجلات ماتحرّكتش.

إعادة الترتيب في المكان (Program 6.14)

طب لو لازم في الآخر السجلات نفسها تترتب؟ التبديلات هتحرك السجل أكتر من مرة. الحل: الـ permutation عبارة عن دورات. امشي في كل دورة: احفظ أول سجل، انقل اللي مكانه، وهكذا لحد ما ترجع. كل سجل بيتنقل مرة واحدة بالظبط (زائد نقلة لكل دورة).

void insitu(dataType data[], int a[], int N)
  { int i, j, k;
    for (i = 0; i < N; i++)
      { dataType v = data[i];
        for (k = i; a[k] != i; k = a[j], a[j] = j)
          { j = k; data[k] = data[a[k]]; }
        data[k] = v; a[k] = k; } }

6.10 Key-Indexed Counting (Program 6.17)

لو المفاتيح أرقام صغيرة من 0 لـ R−1، مش محتاج تقارن خالص! أربع خطوات:

  1. عدّ كل مفتاح: cnt[a[i]+1]++.
  2. حوّل العدّ لمواقع بداية: cnt[j] += cnt[j-1].
  3. وزّع: b[cnt[a[i]]++] = a[i].
  4. انسخ b لـ a.

Property 6.12: زمن خطي لو عدد المفاتيح المختلفة R في حدود ثابت × N. كل عنصر بيتنقل مرتين، وكل مفتاح بيتقرا مرتين.

والأهم: مستقر. في الخطوة 3 بنمشي المدخل بالترتيب، فالمتساويين بيدخلوا بنفس ترتيبهم:

by section (stable): 0:Harris 0:Martin 1:Garcia 1:Jones 2:Anderson 2:Johnson 2:Martinez 3:Brown ...

الخاصية دي هي اللي هيقوم عليها LSD radix sort بالكامل (الدرس 24).

مش «أسرع من N log N» بالسحرkey-indexed counting بيكسر حد N log N لأنه مش بيقارن — بيستخدم المفتاح كفهرس. لو R = 2³² مثلًا، مصفوفة العدّ مستحيلة. الحد الأدنى N log N بيخص خوارزميات المقارنة بس.

ليه متتابعة Shell الأصلية (N/2، N/4، …) سيئة؟

على المدخل المناسب، اللفة الأخيرة بتبقى insertion sort على مصفوفة مش مترتبة → N².
