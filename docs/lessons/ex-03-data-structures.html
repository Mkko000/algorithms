تمارين محلولة · الفصل 3 (Elementary Data Structures) · تمارين 3.11–3.70

الفصل التالت مليان تمارين «إيديك في الكود»: arrays وlinked lists وstrings. عشان كده الدرس ده فيه كود أكتر من الدروس اللي فاتت. والأهم من الكود هو طريقة التفكير: إمتى تستخدم dummy node، وإزاي تتأكّد إن الـ pointers ماضاعتش، وإزاي تقيس بدل ما تخمّن.

هدف الدرس: تتمرّن على الـ list processing من غير أخطاء pointers، وتربط الـ sieve والـ Josephus والأرقام العشوائية بالتحليل اللي اتعلّمته في الفصل 2.
قاعدة ذهبية للـ linked listsقبل ما تكتب أي سطر، ارسم الـ nodes والأسهم على ورقة، ونفّذ الكود بإيدك على list فيها 0 و1 و2 node. معظم الـ bugs بتستخبّى في الحالات الصغيرة دي.

تمرين 3.11: a[i] = a[a[i]]

نص التمرين: لو int a[99]، إيه محتوى المصفوفة بعد السطرين دول؟
for (i = 0; i < 99; i++) a[i] = 98-i;
for (i = 0; i < 99; i++) a[i] = a[a[i]];
بنفكّر إزايالفخ هنا إن اللفّة التانية بتكتب في نفس المصفوفة اللي بتقرا منها. فلازم تسأل لكل i: لما بقرا a[a[i]]، الخانة دي اتعدّلت ولا لسه؟ a[i] = 98−i. لو 98−i > i (يعني i < 49)، الخانة لسه ماتعدّلتش، وفيها 98−(98−i) = i. ولو 98−i < i، الخانة اتعدّلت خلاص.
الحل

لـ i ≤ 49: a[i] = i. ولـ i ≥ 50: a[i] = a[98−i]، والخانة 98−i ≤ 48 اتعدّلت وبقت 98−i، فـ a[i] = 98−i. النتيجة: 0، 1، …، 49، 48، …، 1، 0.

3.11 a[] = 0 1 2 3 ... 47 48 49 48 47 ... 2 1 0

لو كانت اللفّة دي بتكتب في مصفوفة تانية، كان الناتج a[i] = i في كل الخانات. يعني الفرق كله جه من الـ in-place.

تمرين 3.13، 3.15 و3.16: الـ sieve من غير الـ if

نص التمرين: (3.13) استخدم sieve of Eratosthenes (Program 3.5) عشان تعدّ الـ primes الأقل من N، لـ N = 10³…10⁶. (3.15) قيس أثر إنك تشيل الاختبار if (a[i]) اللي قبل الـ inner loop. (3.16) حلّل البرنامج عشان تفسّر اللي لقيته.
بنفكّر إزايبدل ما نقيس بالوقت (اللي بيتأثر بالجهاز)، نعدّ مرات تنفيذ الـ inner loop. مع الاختبار، الـ loop بيشتغل بس لـ i أولي، وبيعمل حوالي N/p − p خطوة. ومن غيره بيشتغل لكل i ≤ √N. يبقى المقارنة بين Σp أولي N/p وΣi N/i. الأولانية حوالي N ln ln √N (نظرية Mertens)، والتانية حوالي N ln √N.

تمرين 3.28، 3.30 و3.33: Josephus

نص التمرين: (3.28) Program 3.9 بيضبط ضعف عدد الـ links اللي محتاجها وهو بيبني الـ list، لأنه بيقفل الدايرة بعد كل insert. عدّله عشان مايعملش الشغل الزيادة ده. (3.30) استخدم Program 3.9 عشان تحسب دالة Josephus لـ M = 2، 3، 5، 10 وN = 10³…10⁶. (3.33) اعمل نسخة بـ array of indices بدل الـ pointers (Figure 3.6).
بنفكّر إزايفي 3.28: ابني الـ nodes في array، وكل node تشاور على اللي بعدها، والأخيرة على الأولى. كده كل link بيتضبط مرة واحدة. وعشان تثق في الأرقام الكبيرة، اعمل تلات نسخ مستقلة: pointers وarray of indices والـ recurrence الرياضي J(N) = (J(N−1) + M − 1) mod N + 1، وقارن بينهم. لو اتفقوا، غالبًا الإجابة صح.
الحل 
small check, N=9 M=5 (Figure 3.5): 8
3.30  J(N,M)        N=1000     10000    100000   1000000
      M=2               977      3617     68929    951425
      M=3               604      2692     92620    637798
      M=5               763       646     40333    718997
      M=10               63      9143     77328    630538
list, index-array and recurrence agree: yes

ولـ M = 2 فيه صيغة مقفولة: لو N = 2^m + L (0 ≤ L < 2^m)، يبقى J = 2L + 1. مثلًا 1000 = 512 + 488، فـ J = 977 ✓. وكود الـ array نسخة طبق الأصل من الـ list، بس x->next بقت next[x]:

for (i = 1; i <= N; i++) next[i] = i % N + 1;
x = N;
while (x != next[x])
  { for (i = 1; i < M; i++) x = next[x];
    next[x] = next[next[x]]; }

والوقت: كل حذف بيعمل M−1 خطوة، يعني O(MN) (ده تمرين 3.29). ولـ M = 10 وN = 10⁶ ده 10⁷ خطوة، أقل من ثانية.

تمرين 3.34، 3.35 و3.36: تحريك nodes

نص التمرين: (3.34) اكتب function تنقل أكبر item في list لآخرها. (3.35) أصغر item لأولها. (3.36) رتّب الـ list بحيث الـ nodes اللي في المواقع الزوجية تيجي بعد اللي في المواقع الفردية، مع الحفاظ على ترتيب كل مجموعة.
بنفكّر إزايعشان تشيل node من list، محتاج الـ node اللي قبلها. فدوّر على «الـ node اللي قبل الأكبر» مش على الأكبر نفسه. ولو الأكبر هو أول node، مفيش node قبلها. الحل: dummy head بيخلّي أول node زي أي node. وفي 3.36: امشي مرة واحدة، ووزّع الـ nodes على list-ين (فردي/زوجي) ليهم tails، وفي الآخر اربط ذيل الفردي براس الزوجي. ومتنساش تقفل ذيل الزوجي بـ NULL.
الحل 
link odd_then_even(link h)
  { struct node od = {0, NULL}, ev = {0, NULL};
    link o = &od, e = &ev;
    for (int pos = 1; h; h = h->next, pos++)
      if (pos % 2) o = o->next = h; else e = e->next = h;
    e->next = NULL; o->next = ev.next;
    return od.next; }

3.34 max to end:        5 2 7 1 8 3 6 4 9
3.35 min to front:      1 5 2 7 8 3 6 4 9
3.36 odd pos, even pos: 1 2 8 6 9 5 7 3 4

تحقّق بنفسك: المواقع الفردية في 1 5 2 7 8 3 6 4 9 هي 1، 2، 8، 6، 9 والزوجية 5، 7، 3، 4. ومفيش ولا malloc: إحنا بنعيد ربط نفس الـ nodes.

تمرين 3.38 و3.39: نسخ وحذف بشرط

نص التمرين: (3.38) function تاخد link لـ list وترجّع link لنسخة منها (list جديدة فيها نفس الـ items بنفس الترتيب). (3.39) function تاخد list وfunction، وتشيل كل item الـ function بترجّع له nonzero.
بنفكّر إزايفي النسخ: الخطأ الشائع إنك تبني الـ list بالـ insert في الأول، فتطلع مقلوبة. الحل: احتفظ بـ tail. وفي الحذف: لما تشيل p->next، ماتتحركش لقدّام، لأن الـ node الجديدة في p->next لسه مااتفحصتش. وده أشهر bug في الموضوع ده: عنصرين ورا بعض لازم يتشالوا، فتشيل الأول وتنط على التاني.
الحل 
link remove_if(link h, int (*bad)(link))
  { struct node d = {0, h}; link p = &d;
    while (p->next)
      if (bad(p->next)) { link t = p->next; p->next = t->next; free(t); }
      else p = p->next;
    return d.next; }
3.38 copy:              1 5 2 7 8 3 6 4 9
3.39 remove evens:      1 9 5 7 3        (from 1 2 8 6 9 5 7 3 4)
original untouched:     1 5 2 7 8 3 6 4 9

لاحظ إن 2 و8 و6 كانوا ورا بعض، واتشالوا كلهم. وإن الأصل ماتأثّرش، لأن الحذف حصل على النسخة.

تمرين 3.53 و3.54: كام node توصل لهم؟ بذاكرة ثابتة

نص التمرين: (3.53) عندك nodes مفيهاش NULL links (كل node بتشاور على نفسها أو على node تانية). أثبت إنك لو بدأت من أي node ومشيت ورا الـ links، هتدخل في دايرة في الآخر. (3.54) اكتب كود يحسب عدد الـ nodes المختلفة اللي هتوصلها من node معيّنة، من غير ما تعدّل أي node، وبذاكرة إضافية ثابتة.
بنفكّر إزاي3.53: عدد الـ nodes محدود، فلو مشيت أكتر من N خطوة لازم تزور node مرتين (pigeonhole). ومن ساعتها هتكرر نفس المشوار للأبد، لأن كل node ليها next واحد بس. يبقى الشكل زي حرف ρ: ذيل طوله μ وبعده دايرة طولها λ. والمطلوب μ + λ. بس ماينفعش تعلّم الـ nodes ولا تخزّنهم. الفكرة: «أرنب وسلحفاة»، two pointers بسرعات مختلفة لازم يتقابلوا جوه الدايرة.
الحل

بطريقة Brent: السلحفاة بتستنّى في مكانها، والأرنب بيجري خطوات بعدد قوى 2 (1، 2، 4، …). أول ما يرجع للسلحفاة، عدد خطواته من آخر «نقلة» = λ. بعد كده حط pointer في البداية وواحد سابقه بـ λ خطوة، وحرّكهم مع بعض. هيتقابلوا بالظبط عند أول node في الدايرة بعد μ خطوة.

3.54 from node 0: tail 7 + cycle 12 = 19 distinct nodes (expected 19)
     from a node on the cycle: tail 0 + cycle 12 = 12

الوقت O(μ + λ) والذاكرة 3 pointers وعدادين. (والتمرين 3.55، إن link-ين يوصلوا لنفس الدايرة؟ احسب λ من الأول، وبعدين اتأكّد إن نقطة من دايرة التاني بتظهر في الـ λ خطوة دول.)

تمرين 3.62: أطول مسافة بأقل قراية

نص التمرين: اكتب برنامج كفؤ يلاقي طول أطول سلسلة مسافات في string، ويبص على أقل عدد ممكن من الحروف. تلميح: البرنامج لازم يبقى أسرع كل ما السلسلة تطول.
بنفكّر إزاينفس فكرة Boyer-Moore: لو أطول سلسلة لقيتها لحد دلوقتي طولها b، ووقفت عند موقع i، بص على i+b بس. لو مش مسافة، يبقى مفيش سلسلة أطول من b ممكن تبدأ في أي مكان من i لـ i+b (أي سلسلة طولها b+1 بتبدأ هناك لازم تغطّي i+b). فنط لـ i+b+1. ولو مسافة، قيس السلسلة اللي حواليها لورا ولقدّام.
