2.1 الأول: نفّذ وقيس (Empirical analysis)

قبل أي معادلة: اكتب البرنامج وشغّله على مدخلات بتكبر. أبسط تجربة وأقواها: اضاعف N وشوف الوقت اتضرب في كام.

  • النسبة ≈ 2 → خطي (N)
  • النسبة ≈ 4 → تربيعي (N²)
  • النسبة شوية فوق 2 → N log N
  • النسبة ≈ 1 → لوغاريتمي أو ثابت

الكتاب بيقسّم المدخلات اللي بنجرّب عليها لـ 3 أنواع: بيانات حقيقية (اللي البرنامج هيشوفها فعلًا)، بيانات عشوائية (عشان نقارن بالتحليل)، وبيانات منحرفة/شريرة (perverse — عشان نكشف أسوأ حالة). البرنامج اللي بيعدّي الاتنين الأولانيين ويقع في التالت هيقع في الإنتاج في يوم.

2.2 التحليل: نعدّ إيه بالظبط؟

الوقت بيعتمد على الجهاز والمترجم والكاش. فبنعزل الحاجات دي ونعدّ العملية الأساسية في اللوب الداخلي (مقارنة، تبديل، لمسة مصفوفة)، كدالة في البارامتر الأساسي N (حجم المدخل). الخطوات:

  1. حدّد العمليات المجرّدة اللي البرنامج مبني عليها (اللوب الداخلي).
  2. اعمل نموذج رياضي للمدخلات (مثلًا: كل الترتيبات متساوية الاحتمال).
  3. احسب عدد مرات تنفيذ كل عملية — في المتوسط وأسوأ حالة.

النتيجة شكلها: زمن ≈ c · f(N)، الثابت c بيجي من التجربة، والدالة f من التحليل. التحليل لوحده من غير قياس ممكن يضلّلك، والقياس من غير تحليل مايقولكش يحصل إيه لما N يبقى أكبر 1000 مرة.

دوال تانية بتتكرر: lg N (لوغاريتم أساس 2: عدد مرات القسمة على 2)، ln N (طبيعي؛ ln N ≈ 0.693 lg N)، والأعداد التوافقية HN = 1 + 1/2 + … + 1/N ≈ ln N + 0.57721 (هتظهر في تحليل quicksort والـ BST)، وN! اللي Stirling بيقرّبه: lg N! ≈ N lg N − 1.44N.

حسّ الرقمعلى جهاز بيعمل مليار عملية في الثانية: N=10⁶ بخوارزمية N² = 10¹² عملية = ربع ساعة. نفس N بـ N lg N ≈ 2·10⁷ = 0.02 ثانية. N=10⁹ بـ N²؟ 30 سنة. ده مش فرق نظري — ده فرق «خلص» و«مات».

2.4 Big-Oh من غير رعب

التعريف: g(N) = O(f(N)) لو في ثابت c و N₀ بحيث g(N) ≤ c·f(N) لكل N > N₀. يعني g «ماتعدّيش» رتبة f. سقف، مش مساواة.

  • O = سقف (upper bound) — «مش أسوأ من».
  • Ω = أرضية (lower bound) — «مش أحسن من».
  • Θ = الاتنين: الرتبة بالظبط.
  • ~ (tilde) = نفس الحد الأكبر بالثابت بتاعه: g ~ f لو g/f → 1. سادجوك بيحب يستخدمها عشان الثابت مهم عمليًا: «~N²/2 مقارنة» أدق من «O(N²)».

ليه Big-Oh مفيدة؟ بتخلّينا نشيل الحدود الصغيرة: 3N² + 100N + 50 = O(N²)، ونكتب حاجات زي N(N−1)/2 = N²/2 + O(N) — الجزء المهم واضح والباقي مكتوب إنه «أصغر». وليه خطيرة؟ لأن O سقف بس: «O(N²)» ممكن تكون خوارزمية خطية فعلًا. وكمان بتخبّي الثوابت: 1000·N أبطأ من N² لحد N=1000.

خلي بالك(l+r)/2 ممكن يعمل overflow لو l و r كبار. المضمون: l + (r-l)/2. تفصيلة صغيرة في التحليل، كارثة في الإنتاج.

ضاعفت N والوقت اتضرب في 4 تقريبًا. الخوارزمية غالبًا…

(2N)² = 4N². ده بالظبط سؤال تجربة الـ doubling.

3N² + 1000N + 7 رتبتها إيه؟

الحد المسيطر N². الـ ~ بتحتفظ بالثابت 3 لأنه بيفرق في المقارنة العملية.

ليه بنجرّب على بيانات «شريرة» (perverse) كمان؟

quicksort الساذج على ملف مترتب أو insertion على مقلوب — بيانات حقيقية جدًا بتطلع شريرة.

إيه الفرق بين O و Θ؟

N = O(N²) صح، بس N مش Θ(N²).

HN = 1 + 1/2 + … + 1/N بتكبر زي إيه؟

HN ≈ ln N + 0.577. هتقابلها في متوسط تكلفة quicksort و BST.
