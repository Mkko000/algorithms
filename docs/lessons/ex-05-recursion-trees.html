تمارين محلولة · الفصل 5 (Recursion and Trees) · تمارين 5.1–5.90

الفصل الخامس أكبر فصل في الجزء الأول، وتمارينه فيها كل حاجة: recursion عادي، وdivide-and-conquer، وdynamic programming، وخصائص الشجر. اخترنا منهم اللي بيعلّمك حاجة: إمتى الـ recursion بيعمق جدًا، وإزاي تحوّل recursion لـ formula، وإزاي تحسب حاجة على شجرة في لفّة واحدة.

هدف الدرس: تكتب recursive functions صح من أول مرة (base case، والمشكلة بتصغر)، تحوّل الـ recursion الأُسّي لـ DP، وتثبت وتقيس خصائص الشجر.
سؤالين قبل أي recursion(1) إيه أصغر حالة، وإجابتها إيه؟ (2) هل كل استدعاء بيقرّب للحالة دي فعلًا؟ لو مش متأكد من التاني، يبقى عندك infinite recursion مستخبّي. وده بالظبط موضوع تمرين 5.40 تحت.

تمرين 5.1 و5.2: lg(N!) وN! mod M

نص التمرين: (5.1) اكتب برنامج recursive يحسب lg(N!). (5.2) عدّل Program 5.1 عشان يحسب N! mod M من غير overflow. جرّبه بـ M = 997 وN = 10³…10⁶، عشان تشوف نظامك بيتعامل إزاي مع الـ recursion العميق.
بنفكّر إزايlg(N!) = lg N + lg((N−1)!)، يعني نفس شكل Program 5.1 بس بنجمع لوغاريتمات بدل ما نضرب، فمفيش overflow. وفي mod: (a·b) mod M = ((a mod M)·(b mod M)) mod M، فخلّي كل نتيجة وسطانية أقل من M. بس قبل ما تشغّل، فكّر: N! لأي N ≥ 997 فيها 997 كعامل. يعني الإجابة 0! التمرين الحقيقي هنا هو عمق الـ recursion.
الحل 
double lgfact(int n) { return n <= 1 ? 0 : log2(n) + lgfact(n-1); }
int factmod(int n, int m)
  { return n == 0 ? 1 % m : (long)n % m * factmod(n-1, m) % m; }
5.1 lg(10!) = 21.7911 (log2(3628800) = 21.7911), lg(100!) = 524.8
5.2   1000! mod 997 =   0  (recursion depth 1001)
5.2 100000! mod 997 =   0  (recursion depth 100001)
    996! mod 997 = 996 by Wilson's theorem = p-1

عمق 100 ألف اشتغل عادي، لأن كل frame صغير. بس عند المليون، على كتير من الأنظمة (stack حجمه 8MB) البرنامج هيقع بـ stack overflow. ودي النقطة اللي سادجوك عايزك تشوفها: recursion عمقه N خطر لـ N كبير، حتى لو الخوارزمية صح. (والأمان إن الـ divide-and-conquer عمقه lg N بس.)

تمرين 5.40–5.43: PN بالـ DP (وفخ في نص التمرين)

نص التمرين: (5.40) استخدم bottom-up DP عشان تحسب PN = ⌊N/2⌋ + P⌊N/2⌋ + P⌈N/2⌉، لـ N ≥ 1 وP₀ = 0، وارسم N مقابل PN − N lg N/2. (5.41) نفس الكلام بـ top-down. (5.43) ارسم عدد الاستدعاءات في الـ top-down.
بنفكّر إزايطبّق السؤالين بتوع الـ tip: لـ N = 1، ⌈1/2⌉ = 1، فالـ recurrence بيقول P₁ = 0 + P₀ + P₁. يعني P₁ بيستدعي نفسه! لو كتبتها top-down حرفيًا، infinite recursion. فلازم base case تاني: P₁ = 0 (وده المعنى المقصود: مسألة حجمها 1 مابتتكلّفش). وبعد كده لاحظ إن الشكل ده هو نفسه عدد مقارنات الـ merge في أحسن حالة.

تمرين 5.44 و5.45: CN بتاع quicksort

نص التمرين: احسب بالـ DP (bottom-up في 5.44، وtop-down في 5.45) CN = N + (1/N) Σ1≤k≤N (Ck−1 + CN−k) لـ N ≥ 1، وC₀ = 1.
بنفكّر إزايالحساب الساذج O(N) لكل CN، يعني O(N²) للكل. بس الحدّين في المجموع متماثلين: Σ(Ck−1 + CN−k) = 2 Σj<N Cj. فخلّي running sum، وكل خطوة تبقى O(1). وده هو الـ recurrence بتاع متوسط مقارنات quicksort (الفصل 7)، فتوقّع ≈ 2N ln N.
الحل

5.45 top-down C_23 = 134.2460 (bottom-up 134.2460), 553 calls

قريب من 2N ln N (الحد الأدق 2(N+1)HN − حدود خطية). والـ top-down الساذج بيعمل 553 استدعاء لـ N = 23 (كل مستوى بيلف على كل اللي قبله)، رغم الـ memo. والـ bottom-up مع الـ running sum أحسن بكتير.

Induction: L(N) = L(⌊N/2⌋) + L(⌈N/2⌉) + N.
