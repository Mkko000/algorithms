لو quicksort هو اللاعب الموهوب اللي ساعات بيضيّع ماتش سهل، mergesort هو اللاعب المضمون: دايمًا N lg N، مهما كان المدخل. وكمان مستقر. التمن الوحيد: مساحة إضافية بحجم N. وفكرته عكس quicksort بالظبط: هناك الشغل كله في القسمة والدمج ببلاش؛ هنا القسمة ببلاش والشغل كله في الدمج.

هدف الدرس: تكتب الدمج بطرقه (منفصل، abstract in-place، bitonic من غير sentinels)، تكتب mergesort من فوق لتحت وتحلّله، وتعرف التحسينات اللي بتخلّيه أسرع: cutoff ومنع النسخ.

8.1 الدمج الثنائي (Program 8.1)

عندك كومتين ورق مترتبين. عايز كومة واحدة مترتبة: بص على الورقة اللي فوق في كل كومة، خد الأصغر، كرّر. كل ورقة بنلمسها مرة واحدة: N + M خطوة.

void mergeAB(Item c[], Item a[], int N, Item b[], int M)
  { int i, j, k;
    for (i = 0, j = 0, k = 0; k < N+M; k++)
      { if (i == N) { c[k] = b[j++]; continue; }
        if (j == M) { c[k] = a[i++]; continue; }
        c[k] = (less(a[i], b[j])) ? a[i++] : b[j++]; } }

لاحظ الاختبارين i == N وj == M في كل لفة — شبه دايمًا false. ده بالظبط اللي التحسين الجاي بيشيله.

8.2 الدمج «في المكان» المجرّد (Program 8.2)

عشان mergesort، الواجهة الأريح: merge(a, l, m, r) — ادمج a[l..m] وa[m+1..r] وسيب الناتج في a[l..r]. التنفيذ بينسخ لـ aux ويدمج راجع. والحيلة الذكية: انسخ النص التاني بالعكس.

void merge(Item a[], int l, int m, int r)
  { int i, j, k;
    for (i = m+1; i > l; i--) aux[i-1] = a[i-1];
    for (j = m; j < r; j++) aux[r+m-j] = a[j+1];
    for (k = l; k <= r; k++)
      if (less(aux[j], aux[i]))
           a[k] = aux[j--]; else a[k] = aux[i++]; }

دلوقتي aux «bitonic»: بيطلع وبعدين ينزل. i ماشي من الشمال وj من اليمين. لما واحد فيهم يخلص نصه، هيقابل أكبر عنصر في النص التاني — وده بيشتغل sentinel تلقائي. مفيش اختبارات حدود، ومفيش قيمة «لا نهائية» محتاجين نعرفها.

التمن الخفي: الثباتالكتاب بينبّه إن الدمج الـ bitonic ده مش مستقر: لما المفاتيح تتساوى ممكن ياخد من النص التاني الأول. لو الثبات مهم، استخدم الدمج العادي باختبارات الحدود، واكتب الشرط بحيث يفضّل النص الأول عند التساوي.

8.3 Mergesort من فوق لتحت (Program 8.3)

void mergesort(Item a[], int l, int r)
  { int m = (r+l)/2;
    if (r <= l) return;
    mergesort(a, l, m);
    mergesort(a, m+1, r);
    merge(a, l, m, r); }

ودي divide-and-conquer الكلاسيكية (الدرس 11). شجرة الريكيرشن متوازنة تمامًا، وشكلها بيعتمد على N بس — مش على القيم. ده الفرق الجوهري عن quicksort.

8.4 التحسينات (Program 8.4)

1. Cutoff للملفات الصغيرة

زي quicksort بالظبط: الريكيرشن عنده عدد ضخم من النداءات الصغيرة. insertion sort لأي جزء ≤ 10 بيحسّن الوقت 10–15% (رقم الكتاب).

2. من غير نسخ

كل merge بينسخ لـ aux وبعدين يدمج راجع — يعني كل عنصر بيتنقل مرتين في كل مستوى. الحيلة: خلّي الريكيرشن يبدّل أدوار المصفوفتين في كل مستوى. الجزء الأسفل يرتّب في b، والدمج يحط الناتج في a، والمستوى اللي فوقه بيعكس.

void mergesortABr(Item a[], Item b[], int l, int r)
  { int m = (l+r)/2;
    if (r-l <= 10) { insertion(a, l, r); return; }
    mergesortABr(b, a, l, m);
    mergesortABr(b, a, m+1, r);
    mergeAB(a+l, b+l, m-l+1, b+m+1, r-m); }
void mergesortAB(Item a[], int l, int r)
  { int i;
    for (i = l; i <= r; i++) aux[i] = a[i];
    mergesortABr(a, aux, l, r); }

الكتاب بيوصفه بإنه «برنامج tricky». ليه شغال؟ لأن نسخة واحدة في الأول بتخلّي a وaux فيهم نفس البيانات، فالـ insertion sort في الأوراق بيرتّب في المكان الصح أيًا كانت المصفوفة. والتمن: رجعت اختبارات الحدود في الدمج (مفيش bitonic). وفيه نسخة «للخبراء» بأربع روتينات (تصاعدي وتنازلي) بترجّع الـ bitonic — الكتاب بيقول إن كل التحسينات مع بعض بتسرّع mergesort حوالي 40%، بس لسه أبطأ من quicksort بحوالي 25%.

3. تخطّي الدمج لو الجزئين مترتبين أصلًا

لو a[m] ≤ a[m+1]، الجزئين مع بعض مترتبين — ماتدمجش. الكتاب بيشاور على الفكرة دي لما فيه ترتيب كتير في المدخل.
