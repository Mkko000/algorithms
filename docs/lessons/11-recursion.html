ناس كتير بتتعامل مع الريكيرشن كأنه سحر: «الدالة بتنادي نفسها؟ طب هتعرف إمتى تقف؟». الحقيقة أبسط: الريكيرشن هو ترجمة مباشرة لتعريف رياضي، والكمبيوتر بيشيل الشغل الإداري بـ stack داخلي. المشاكل بتيجي لما تنسى شرط الوقوف، أو لما الريكيرشن يتفرّع ويعيد نفس الشغل.

هدف الدرس: تكتب دوال ريكيرسف صحيحة وتعرف تثبت إنها بتقف، تفهم عمق الريكيرشن وتكلفته، وتتقن divide-and-conquer من خلال: أقصى عنصر، أبراج هانوي، ورسم المسطرة — وتشوف العلاقة السرّية بين هانوي والمسطرة.

5.1 الخوارزميات الريكيرسف

تعريف سادجوك: خوارزمية ريكيرسف = بتحل المشكلة بحل نسخ أصغر من نفس المشكلة. في C: دالة بتنادي نفسها. لازم حاجتين: حالة قاعدة بترجّع من غير نداء، وكل نداء ريكيرسف يكون على قيمة أصغر بتقرّب من القاعدة.

/* Program 5.1 */
int factorial(int N)
  { if (N == 0) return 1;
    return N*factorial(N-1); }

وتقدر تثبت إنها صح بالاستقراء الرياضي: صح لـ 0، ولو صح لـ N−1 يبقى صح لـ N. البرنامج الريكيرسف هو البرهان بالاستقراء مكتوب كود.

برنامج مشكوك فيه (Program 5.2)

int puzzle(int N)
  { if (N == 1) return 1;
    if (N % 2 == 0) return puzzle(N/2);
    else return puzzle(3*N+1); }

هل الدالة دي بتقف لكل N؟ ماحدش في العالم يعرف! (دي مسألة Collatz.) النداء على 3N+1 مش «أصغر»، فمفيش ضمان. ده درس: لو مش قادر تثبت إن المعامل بيصغر، مش قادر تثبت إن البرنامج بيقف.

puzzle(3)  reached 1 after 8 calls
puzzle(27) reached 1 after 112 calls     ← 27 بتطلع لحد 9232 قبل ما تنزل

Euclid (Program 5.3) وتقييم prefix (Program 5.4)

gcd(m, n) = gcd(n, m % n) — المعامل التاني بيصغر بسرعة (لوغاريتمي)، فالعمق صغير. أما تقييم تعبير prefix زي * + 7 * * 4 6 + 8 9 5 فهو ريكيرشن طبيعي: «التعبير إما رقم، أو عملية وبعدها تعبيرين». الدالة بتمشي في النص بمؤشر عام وبتنادي نفسها مرتين للمعاملين:

int eval()
  { int x = 0;
    while (a[i] == ' ') i++;
    if (a[i] == '+') { i++; return eval() + eval(); }
    if (a[i] == '*') { i++; return eval() * eval(); }
    while (a[i] >= '0' && a[i] <= '9') x = 10*x + (a[i++]-'0');
    return x; }

الريكيرشن على القوائم (Program 5.5)

القايمة تعريفها ريكيرسف (الدرس 06)، فالدوال عليها طبيعية: count(x) = 0 لو فاضية، وإلا 1 + count(x->next). والطباعة بالعكس؟ بدّل ترتيب سطرين: نادي على الباقي الأول، بعدين اطبع.

count=6  forward: 5 1 5 2 5 3  reverse: 3 5 2 5 1 5
after delete 5: 1 2 3  (count=3)
عمق الريكيرشن = ذاكرةكل نداء بياخد مكان في الـ stack. count على قايمة مليون عنصر = مليون frame، وغالبًا هيعمل stack overflow. سادجوك بينبّه إن الدوال البسيطة دي على القوائم الأحسن تتكتب loop في الممارسة، وإن الريكيرشن هنا للفهم. القاعدة: لو العمق ممكن يبقى N، فكّر في نسخة غير ريكيرسف. لو العمق log N (زي gcd)، مفيش قلق.

5.2 فرّق تسد (Divide and Conquer)

قسّم المشكلة لجزئين (غالبًا نصين)، حل كل جزء ريكيرسف، اجمع النتيجتين.

أقصى عنصر (Program 5.6)

Item max(Item a[], int l, int r)
  { Item u, v; int m = (l+r)/2;
    if (l == r) return a[l];
    u = max(a, l, m);
    v = max(a, m+1, r);
    if (u > v) return u; else return v; }

مش أسرع من loop عادي، بس هو نموذج للشكل. Property 5.1: دالة بتقسّم مشكلة حجمها N لجزئين مستقلين غير فاضيين وبتحلّهم ريكيرسف، بتنادي نفسها أقل من N مرة (لو عدّينا النداء الأصلي مع الأوراق: 2N−1). على 11 عنصر قسناها: 21 نداء بالظبط.

أبراج هانوي (Program 5.7)

عشان تنقل N قرص: انقل N−1 للعمود المساعد، انقل الأكبر، انقل الـ N−1 فوقه. Property 5.2: عدد النقلات T(N) = 2T(N−1) + 1 = 2^N − 1. لـ 64 قرص بنقلة في الثانية؟ أكتر من 5 مليار قرن.

void hanoi(int N, int d)
  { if (N == 0) return;
    hanoi(N-1, -d);
    shift(N, d);
    hanoi(N-1, -d); }

المسطرة (Programs 5.8–5.9) والسر

عايز ترسم علامات مسطرة: علامة طويلة في النص، أقصر عند الأرباع، أقصر عند الأثمان… ده نفس شكل هانوي بالظبط:

void rule(int l, int r, int h)
  { int m = (l+r)/2;
    if (h > 0)
      { rule(l, m, h-1);
        mark(m, h);
        rule(m, r, h-1); } }

والملاحظة الحلوة: القرص اللي بيتنقل في الخطوة رقم k في هانوي = طول علامة المسطرة رقم k = 1 + عدد الأصفار في آخر k بالثنائي. يعني تقدر تحل هانوي من غير ريكيرشن خالص: القرص الصغير بيتحرك كل نقلة فردية، والنقلات الزوجية ليها حركة واحدة ممكنة.

height(i) = 1 + trailing zeros of i: 1 2 1 3 1 2 1 4 1 2 1 3 1 2 1
