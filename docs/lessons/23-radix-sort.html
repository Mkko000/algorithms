لما بتدوّر على كلمة في قاموس ورقي، مابتعملش binary search بمقارنة الكلمة كلها. بتفتح على حرف «س»، وبعدين «سي»، وبعدين «سيا»… بتستخدم المفتاح حرف حرف. ده الـ radix sorting: بدل ما نقارن مفاتيح كاملة، بنبص على «أرقام» (digits) جوه المفتاح. والنتيجة؟ خوارزميات ممكن تكسر حد N log N، وأحيانًا مابتقراش أغلب البيانات أصلًا.

هدف الدرس: تتقن لغة البتات والبايتات وماكرو digit، تكتب binary quicksort، وتكتب MSD radix sort على نصوص وتفهم «مشكلة الصناديق الفاضية» وحلها.

10.1 بتات وبايتات وكلمات

Definition 10.1: البايت = متتابعة بتات طولها ثابت؛ والنص (string) = متتابعة بايتات طولها متغيّر؛ والكلمة (word) = متتابعة بايتات طولها ثابت. والـ radix sort بيشوف المفتاح كرقم في أساس R = 2^bitsbyte.

#define bitsword  32
#define bitsbyte   8
#define bytesword  4
#define R (1 << bitsbyte)
#define digit(A, B) (((A) >> (bitsword-((B)+1)*bitsbyte)) & (R-1))

digit(A, B) بيرجّع الـ «رقم» رقم B من الشمال. يعني: زق المفتاح يمين لحد ما البايت المطلوب يبقى في الآخر، وبعدين امسك آخر bitsbyte بت بالـ mask.

key 0xCAFEBABE: bytes (digits, R=256): CA FE BA BE   first 8 bits:11001010

واختيار R بيوازن بين حاجتين: R كبير = لفّات أقل على المفتاح، بس كل لفّة محتاجة R عدّاد. R = 2 (بت بت) أبسط حاجة، R = 256 (بايت) الأشهر، R = 65536 بيبقى منطقي لو N ضخم.

لغة C والبتاتاستخدم unsigned دايمًا مع الإزاحة لليمين. على signed int سالب، >> ممكن يملا بـ 1 من الشمال (حسب المترجم)، والـ digit يطلع زبالة.

10.2 Binary Quicksort (Program 10.1)

quicksort بس الـ «pivot» بت مش مفتاح: كل المفاتيح اللي أول بت فيها 0 على الشمال، و1 على اليمين. وبعدين كرّر على كل نص بالبت التاني.

void quicksortB(Item a[], int l, int r, int w)
  { int i = l, j = r;
    if (r <= l || w > bitsword) return;
    while (j != i)
      { while (digit(a[i], w) == 0 && (i < j)) i++;
        while (digit(a[j], w) == 1 && (j > i)) j--;
        exch(a[i], a[j]); }
    if (digit(a[r], w) == 0) j++;
    quicksortB(a, l, j-1, w+1);
    quicksortB(a, j, r, w+1); }

(هنا digit بـ bitsbyte = 1، يعني بت.) مفيش ولا مقارنة مفاتيح. والميزة الكبيرة على quicksort: القسمة تقريبًا في النص دايمًا لو البتات عشوائية — مفيش pivot وحش.

Property 10.2: على مفاتيح بتاتها عشوائية، binary quicksort بيفحص حوالي N lg N بت في المتوسط. نفس recurrence الـ quicksort المثالي: C(N) = 2C(N/2) + N. (التحليل الدقيق ده من كلاسيكيات Knuth.)

N=65536 random keys: 1750631 bits examined, N lg N = 1048576

(عدّادنا بيحسب كل نظرة على بت في المسحين، فالثابت أكبر شوية — بس الرتبة نفسها.)

عيوبهلو المفاتيح كلها بتبدأ بنفس البتات (أرقام صغيرة في int 32 بت مثلًا)، أول كذا لفة مبتعملش حاجة وبتلف على الملف كله. ولو فيه مفاتيح مكررة كتير، بيوصل لآخر بت. والمفاتيح لازم تبقى بطول ثابت أو يتعامل مع آخر النص.

10.3 MSD Radix Sort (Program 10.2)

عمّم من بت لبايت: اعمل key-indexed counting (الدرس 16) على أول بايت → R «صندوق»، كل صندوق فيه المفاتيح اللي بتبدأ بنفس الحرف. وبعدين رتّب كل صندوق ريكيرسف على البايت التاني.

#define bin(A) l+count[A]
void radixMSD(Item a[], int l, int r, int w)
  { int i, j, count[R+1];
    if (w > bytesword) return;
    if (r-l <= M) { insertion(a, l, r); return; }
    for (j = 0; j < R; j++) count[j] = 0;
    for (i = l; i <= r; i++)
      count[digit(a[i], w) + 1]++;
    for (j = 1; j < R; j++)
      count[j] += count[j-1];
    for (i = l; i <= r; i++)
      aux[count[digit(a[i], w)]++] = a[i];
    for (i = l; i <= r; i++) a[i] = aux[i-l];
    radixMSD(a, l, bin(0)-1, w+1);
    for (j = 0; j < R-1; j++)
      radixMSD(a, bin(j), bin(j+1)-1, w+1); }

بعد التوزيع، count[j] بقى بداية الصندوق j+1، فـ bin(j)..bin(j+1)-1 هو الصندوق j+1. والنسخة دي للمفاتيح ثابتة الطول (كلمات بـ bytesword بايت).

النصوص في C: الكتاب بيقول: شيل أول if وأول نداء ريكيرسف. ليه؟ البايت 0 هو آخر النص. فصندوق 0 فيه مفاتيح خلصت ومتساوية لحد هنا — مفيش حاجة تترتب فيه. ملفنا بيشتغل على مصفوفة مؤشرات char *، فاللي بيتنقل في aux مؤشرات مش نصوص:

are by sea seashells seashells sells sells she she shells shore surely the the

مشكلة الصناديق الفاضية

دي النقطة اللي الكتاب بيركّز عليها. كل نداء بيلف على R = 256 عدّاد حتى لو الملف فيه عنصرين. وشجرة الريكيرشن فيها عدد مهول من الملفات الصغيرة (زي quicksort). Property 10.3: كل نداء محتاج على الأقل 2N + 2R خطوة — فلو N = 2 وR = 256، أبطأ لحد 128 مرة من مجرد مقارنة العنصرين.

N=100000 random 20-letter keys, R=256:
  no cutoff (empty-bins problem)     0.016s  counter ops=  21441024  bytes read by counting=420436
  cutoff M=16 to insertion sort      0.004s  counter ops=    539904  bytes read by counting=300000

من غير cutoff: 21 مليون عملية على عدّادات، عشان نرتّب 100 ألف مفتاح! بالـ cutoff: 40 مرة أقل، والوقت 4 مرات أسرع. الكتاب بيقترح حلول تانية كمان: R أصغر من حجم الملف، أو تتخطّى الصناديق الفاضية بشكل أذكى. القاعدة: radix sort للملفات الكبيرة، وحاجة بسيطة للصغيرة.

ولاحظ العمود الأخير: من 2 مليون بايت في البيانات، القراءة كانت 15–21% بس. MSD بيقف أول ما المفاتيح تتميّز عن بعض — ده الـ «sublinear» اللي هنتكلم عنه في الدرس 24.

MSD = trie مستخبيشجرة الريكيرشن بتاعة MSD هي بالظبط trie للمفاتيح: كل عقدة R ابن، وكل مسار من الجذر = بادئة. هنشوف الـ trie نفسه كهيكل بحث في الدرس 35 — نفس الشجرة، بس متخزّنة بدل ما تتبني وتتهد.
