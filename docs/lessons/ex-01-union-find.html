تمارين محلولة · الفصل 1 (Introduction) · تمارين 1.4–1.26

الدرس ده مش شرح جديد. ده قعدة حل تمارين: بناخد تمارين من آخر الفصل الأول في كتاب سادجوك ونحلها مع بعض. في كل تمرين هتلاقي نص التمرين، وبعده بنفكّر إزاي (الطريق اللي يوصّلك للحل، مش الحل نفسه)، وبعدين الحل كامل. والأرقام كلها طالعة من برامج حقيقية في الريبو، مش من دماغي.

هدف الدرس: تتمرّن على تتبّع الـ union-find بإيدك، وتعرف تقدّر وقت التشغيل من غير ما تشغّل، وتشوف بنفسك ليه الـ weighting أهم من الـ path compression.
نصيحة قبل ما تبدأاقرا نص التمرين، واقفل عينك دقيقتين وحاول. بعد كده افتح «بنفكّر إزاي» بس، وجرّب تاني. الحل في الآخر خالص. مفيش حد اتعلّم خوارزميات وهو بيقرا حلول جاهزة.

تمرين 1.12: متوسط المسافة في أسوأ شجرة weighted

نص التمرين: احسب متوسط المسافة من node للـ root في أسوأ شجرة (worst-case tree) فيها 2ⁿ node، مبنية بـ weighted quick union.
بنفكّر إزايإيه هي أسوأ حالة؟ Figure 1.8: كل union بيدمج شجرتين حجمهم واحد. شجرة 2ⁿ تبقى شجرتين 2ⁿ⁻¹ واحدة اتعلّقت تحت root التانية. يبقى عدد الـ nodes على عمق k هو T(n,k) = T(n−1,k) + T(n−1,k−1)، وده بالظبط قانون مثلث باسكال. يعني العدد = C(n,k) (دي اسمها binomial tree، وهتقابلها تاني في الفصل 9).
الحل

المتوسط = (1/2ⁿ) Σ k·C(n,k) = (1/2ⁿ) · n·2ⁿ⁻¹ = n/2. والبرنامج بيأكّد ده بالظبط:

2^4  =     16 nodes: average distance 2.000 (n/2 = 2.0), max 4
2^8  =    256 nodes: average distance 4.000 (n/2 = 4.0), max 8
2^16 =  65536 nodes: average distance 8.000 (n/2 = 8.0), max 16

يعني حتى في أسوأ حالة، المتوسط نص الـ lg N.

تمرين 1.16 و1.19: full path compression، ولوحده مش كفاية

نص التمرين: (1.16) وضّح إزاي تعدّل Program 1.3 عشان يعمل full path compression: كل node لمسناها في الـ union تشاور على root الشجرة الجديدة. (1.19) اديني مثال يبيّن إن إضافة full path compression لـ quick union من غير weighting مش كفاية عشان تضمن إن مفيش paths طويلة.
بنفكّر إزايللـ 1.16: لفّة أولى نلاقي فيها الـ root، ولفّة تانية نمشي فيها نفس الطريق تاني ونخلّي كل node تشاور على الـ root. وللـ 1.19: فكّر في الضعف اللي في الحل نفسه. الـ compression بيصلّح paths بعد ما الـ find يمشيها. فلو لقيت تسلسل الـ find فيه دايمًا بيبدأ من root، الشجرة هتطول من غير ما حد يلمسها.
الحل 
int root(int x)
  { int i = x;
    while (i != id[i]) i = id[i];          /* pass 1: find the root   */
    while (x != i)                          /* pass 2: point all at it */
      { int next = id[x]; id[x] = i; x = next; }
    return i; }

وبعد كده الـ union زي Program 1.3 بالظبط: i = root(p); j = root(q);. وللـ 1.19: الأزواج 0-1, 1-2, 2-3, …, 8-9 مع quick union (اللي بيعمل id[i] = j دايمًا). كل زوج الطرف الشمال فيه root، فالـ find بياخد 0 خطوات:

 8-9   1 2 3 4 5 6 7 8 9 9   3
 depth of node 0 after the chain: 9 (= N-1)

path طولها N−1. ولو بعد كده سألت عن 0، هتدفع N−1 خطوة مرة واحدة والشجرة تتسطّح. فمتوسط التكلفة على المدى الطويل مش وحش (ده تحليل Tarjan)، بس مفيش ضمان لكل عملية، ومن غير الـ weighting مفيش lg N.

تمرين 1.20 و1.21: union by height

نص التمرين: عدّل Program 1.3 عشان يستخدم ارتفاع الشجر (أطول path لحد الـ root) بدل الحجم في قرار مين يبقى ابن مين. اعمل تجارب تقارن بيه مع Program 1.3. (1.21) وضّح إن Property 1.3 لسه صحيحة مع النسخة دي.
بنفكّر إزايخزّن h[i] لكل root. لما تدمج شجرتين ارتفاعهم مختلف، علّق القصيرة تحت الطويلة، والارتفاع مش هيتغيّر. لو متساويين، الارتفاع يزيد 1. وللإثبات: عايز تثبت إن شجرة ارتفاعها h فيها ≥ 2ʰ node. بالـ induction: الارتفاع بيزيد لـ h+1 بس لما ندمج شجرتين ارتفاعهم h، وكل واحدة فيها ≥ 2ʰ، يبقى المجموع ≥ 2ʰ⁺¹.
الحل 
if (h[i] < h[j]) id[i] = j;
else if (h[i] > h[j]) id[j] = i;
else { id[j] = i; h[i]++; }

الإثبات: من الـ induction اللي فوق، N ≥ 2ʰ، يعني h ≤ lg N. فالـ find بيمشي ≤ lg N، والزوج ≤ 2 lg N: Property 1.3 صحيحة. وفي التجربة (أزواج عشوائية لحد ما الكل يتوصّل، ونفس الأزواج للنسختين):

تمرين 1.22–1.24: كام edge عشوائي عشان الكل يتوصّل؟

نص التمرين: عدّل Program 1.4 عشان يولّد أزواج عشوائية بين 0 وN−1 بدل ما يقرا من الـ input، ويفضل يلف لحد ما يعمل N−1 union. شغّله لـ N = 10³، 10⁴، 10⁵، 10⁶، واطبع عدد الـ edges الكلي. (1.24) اديني صيغة تقريبية للعدد ده بدلالة N.
بنفكّر إزايلاحظ إن آخر object منعزل هو اللي بيأخّر كل حاجة. ده شبه مسألة الـ coupon collector: عشان «تلمس» كل الـ N object بأزواج عشوائية محتاج حوالي (N ln N)/2 زوج (كل زوج بيلمس اتنين). ولما كل object يتلمس، الرسم العشوائي غالبًا بيبقى متوصّل (ده من نظرية Erdős–Rényi). يبقى التخمين: ½ N ln N. والتجربة هي اللي تحكم.
