الـ quicksort الأساسي كويس. بس الفرق بين «كويس» و«المكتبة القياسية» هو أربع تحسينات صغيرة، كل واحدة بتعالج نقطة ضعف محددة. وفي الآخر هنستخدم نفس الـ partition عشان نحل مسألة مختلفة: لاقي الوسيط من غير ما ترتّب.

هدف الدرس: تعرف تعمل cutoff للملفات الصغيرة، تختار الـ pivot بـ median-of-three، تتعامل مع المفاتيح المكررة بـ 3-way partitioning، تفهم تكلفة ترتيب النصوص، وتلاقي العنصر رقم k في زمن خطي.

7.4 الملفات الصغيرة

شجرة الريكيرشن بتاعة quicksort فيها عدد ضخم من النداءات على ملفات صغيرة جدًا (2، 3، 5 عناصر). لكل واحد منهم overhead نداء دالة وpartition كامل. وعلى الملفات الصغيرة، insertion sort أسرع. فـ:

if (r-l <= M) { insertion(a, l, r); return; }

وفيه طريقة أبسط وأسرع شوية بيقترحها الكتاب: سيب الملفات الصغيرة من غير ترتيب خالص (if (r-l <= M) return;)، وفي الآخر اعمل insertion sort واحد على المصفوفة كلها. ليه ده شغال؟ لأن كل عنصر بعيد عن مكانه بأقل من M خانة، فالـ insertion sort خطي تقريبًا (Property 6.4، الدرس 15).

cutoff M (random N=100000): M=0:2148169 M=5:2149097 M=10:2136412 M=15:2154814 M=20:2189483 ...

عدد المقارنات تقريبًا ثابت من M = 5 لـ 20 (الكتاب: «اختيار القيمة بالظبط مش حرج»)، والكسب الحقيقي في الوقت لأن مقارنات insertion أرخص ومفيش نداءات. الكتاب بيقول حوالي 10%، وقسنا عندنا:

7.5 Median-of-Three (Program 7.4)

بدل ما تاخد a[r] كـ pivot على العمياني، خد وسيط تلات عناصر: الأول والنص والآخر. تلات مكاسب:

  1. الأسوأ بقى نادر جدًا: عشان يحصل N²، لازم اتنين من التلاتة يبقوا من الأكبر أو الأصغر — في كل partition تقريبًا. وأهم حاجة: الملف المترتب بقى أحسن حالة بدل أسوأ.
  2. Sentinels مجانية: بعد ما ترتّب التلاتة، a[l] ≤ pivot ≤ a[r] — فالـ loops مش محتاجة شروط حدود.
  3. المتوسط بيقل حوالي 5% لأن القسمة بقت أقرب للنص.
void quicksort(Item a[], int l, int r)
  { int i;
    if (r-l <= M) return;
    exch(a[(l+r)/2], a[r-1]);
    compexch(a[l], a[r-1]);
    compexch(a[l], a[r]);
    compexch(a[r-1], a[r]);
    i = partition(a, l+1, r-1);
    quicksort(a, l, i-1);
    quicksort(a, i+1, r); }
void sort(Item a[], int l, int r)
  { quicksort(a, l, r); insertion(a, l, r); }
sorted  N=4000 (naive pivot): 8005998 compares
sorted  N=4000 (median-of-3):   51820 compares       ← 150 مرة أقل
median-of-3 + M=10 (Program 7.4): 1879313 compares   ← vs 2148169

الكتاب بيقول median-of-3 مع cutoff بيوفّروا 20–25% من الوقت. على جهاز حديث بـ -O2 قسنا أقل من كده (~7–10%) — والكتاب نفسه بينبّه إن المترجمات والمعالجات الحديثة بتقلّل قيمة التحسينات الصغيرة. الدرس: قيس على جهازك قبل ما تصدّق أي رقم.

7.6 المفاتيح المكررة (Program 7.5)

ملفات حقيقية كتير فيها تكرار ضخم: ترتيب موظفين بسنة الميلاد، أو طلبات بالحالة («مدفوع»، «مستني»، «ملغي»). quicksort العادي بيتعامل معاها كويس (عشان بيوقف عند المساوي)، بس لسه بيكرر شغل: ملف كله مفاتيح متساوية بيتقسم ويتقسم بلا فايدة.

الأسوأ: لو كتبت الـ partition بحيث يعدّي المساويين بدل ما يقف عندهم:

all 20000 keys equal, stop on equal  :    262058 compares
all 20000 keys equal, scan over equal: 399960001 compares (quadratic)

الحل: 3-way partitioning — قسّم لتلات أجزاء: أصغر، مساوي، أكبر، والجزء المساوي يتشال من الريكيرشن خالص. فكرة Bentley وMcIlroy اللي في الكتاب ذكية: أثناء المسح العادي، أي عنصر مساوي للـ pivot اتنقل في التبديل، ابعته لأطراف المصفوفة (الشمال لحد p، واليمين من q). لما المؤشرين يتقابلوا، رجّع الأطراف دي للنص.

exch(a[i], a[j]);
if (eq(a[i], v)) { p++; exch(a[p], a[i]); }
if (eq(v, a[j])) { q--; exch(a[q], a[j]); }
...
exch(a[i], a[r]); j = i-1; i = i+1;
for (k = l;   k <= p; k++, j--) exch(a[k], a[j]);
for (k = r-1; k >= q; k--, i++) exch(a[k], a[i]);
quicksort(a, l, j);
quicksort(a, i, r);
10 distinct keys, standard : 1719494 compares
10 distinct keys, 3-way    :  409686 compares      ← 4 مرات أقل

والجميل: لو مفيش تكرار، التكلفة الزيادة تقريبًا صفر (اختبار eq بعد كل تبديل بس). وعلى عدد ثابت من المفاتيح المختلفة، الوقت بيبقى خطي.

ملاحظة على نص الكتابالطبعة المطبوعة من Program 7.5 مكتوب فيها k < p وk > q، فعنصر مساوي واحد من كل طرف مابيرجعش للنص. الترتيب بيفضل صح (العنصر بيتعالج في الريكيرشن)، بس بيضيّع شوية من الفايدة. الكتاب نفسه بيستخدم <= و>= لما بيكرر نفس الكود في Program 10.3، وده اللي في ملفنا.

7.7 النصوص والـ vectors

لو المفاتيح نصوص، كل less بقت strcmp — ودي تكلفتها على قد البادئة المشتركة. ولما quicksort بيقرّب للآخر، العناصر في كل جزء بتتشابه أكتر وأكتر (كلها بتبدأ بنفس الحروف)، فالمقارنات بتغلى.

random 5-letter words:   key compares=74029  char compares=137130   (1.9 chars/compare)
long common prefix:      key compares=76252  char compares=2159310  (28.3 chars/compare)

نفس عدد المقارنات تقريبًا، بس 15 مرة حروف أكتر لما النصوص بتبدأ بـ https://example.com/users/. الكتاب بيقترح الحل: لو عارف إن كل النصوص في الجزء ده بتتفق في أول d حرف، ابدأ المقارنة من الحرف d. ولو عملت 3-way partitioning على حرف واحد بدل المفتاح كله، والجزء المساوي تكمّله على الحرف اللي بعده — يطلعلك 3-way radix quicksort (الدرس 23). ونفس الفكرة للـ vectors (مفاتيح متعددة المكوّنات): رتّب بالمكوّن الأول، والمساوي فيه رتّبه بالتاني.

وفيه نقطة مهمة من جدول الكتاب على ملف كلمات حقيقي: 3-way partitioning كان أسرع من qsort بتاع النظام بـ 30–35%، والنسخة اللي بتعدّي المساويين بقت تربيعية بسبب الكلمات المتكررة.

7.8 الاختيار (Selection)

عايز الوسيط، أو أكبر 100 درجة، أو العنصر رقم k؟ مش محتاج ترتّب كله. اعمل partition: لو الـ pivot وقع في مكان k، خلصت. لو k أصغر، كمّل في الشمال بس. لو أكبر، في اليمين بس. ده Hoare برضه.

/* Program 7.6 */
void select(Item a[], int l, int r, int k)
  { int i;
    if (r <= l) return;
    i = partition(a, l, r);
    if (i > k) select(a, l, i-1, k);
    if (i < k) select(a, i+1, r, k); }

/* Program 7.7: the recursion is tail recursion, so make it a loop */
void select(Item a[], int l, int r, int k)
  { while (r > l)
      { int i = partition(a, l, r);
        if (i >= k) r = i-1;
        if (i <= k) l = i+1; } }

Property 7.4: الاختيار بالـ quicksort خطي في المتوسط. الفكرة: كل partition بيقسم تقريبًا في النص، فالشغل N + N/2 + N/4 + … ≈ 2N. والتحليل الدقيق (أصعب بكتير من بتاع quicksort) بيدّي متوسط 2N + 2k ln(N/k) + 2(N−k) ln(N/(N−k)) — خطي لأي k. ولـ k = N/2: حوالي (2 + 2 ln 2) N ≈ 3.39N مقارنة لإيجاد الوسيط.

median of 200000 random ints = 1071180366
compares = 715327   (2+2ln2)N = 677259   vs sorting ~2N lnN = 4882429

أسوأ حالة الـ selectionزي quicksort: N² لو الـ pivot وحش دايمًا. نفس العلاج (عشوائي أو median-of-3). ومن برّه الكتاب للمعلومة: فيه خوارزمية خطية في الأسوأ (median of medians، 1973)، بس ثابتها كبير فعمليًا الكل بيستخدم النسخة دي بـ pivot كويس.
