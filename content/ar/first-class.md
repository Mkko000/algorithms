## 4.8 First-Class ADTs

**تعريف:** first-class data type = نوع تقدر تعمل منه متغيرات كتير، تديها لدوال، وترجّعها من دوال. `int` و `double` first-class. الـ stack بتاع الدرس 08 لأ.

### المثال الأول: الأعداد المركّبة

Program 4.13 عميل بسيط: يحسب الـ N جذور للواحد (*roots of unity*) ويتأكد إن كل جذر أُس N بيدّي 1. أول تنفيذ (4.14–4.15) struct مكشوف:

```c listing="Program 4.13"
typedef struct { float Re; float Im; } Complex;
Complex COMPLEXmult(Complex a, Complex b);
```

شغال وسريع، بس العميل شايف `Re` و `Im` وممكن يلمسهم. لو بكره عايز تخزّن بالصورة القطبية (r, θ)، كل عميل لمس الحقول هيتكسر.

التنفيذ التاني (4.16–4.17) بيستخدم **الحيلة المحورية في الفصل**:

```c
/* COMPLEX.h — the client sees only this */
typedef struct complex *Complex;    /* pointer to an incomplete type */
Complex COMPLEXinit(float, float);
float   Re(Complex);  float Im(Complex);
Complex COMPLEXmult(Complex, Complex);

/* COMPLEX.c — only here is the struct defined */
struct complex { float Re; float Im; };
```

العميل معاه مؤشر لحاجة مايعرفش جواها إيه. المترجم نفسه هيمنعه يكتب `c->Re`. ده أقرب حاجة في C لـ «private» في اللغات الأحدث.

```
8 roots of unity (struct version):
 1  0.707  0.707   ^8 =  1.000  0.000
 3 -0.707  0.707   ^8 =  1.000  0.000 ...
first-class version, root 1 ^ 8:  1.000  0.000
```

:::oops التمن: مين يعمل free؟
كل `COMPLEXmult` بترجّع كائن جديد متحجز بـ malloc. في تعبير زي `mult(mult(a,b),c)` الناتج الوسيط محدش ماسكه — تسرّب. الكتاب بيعترف إن ده العيب الكبير للـ first-class ADTs في C: لازم واجهة فيها `destroy`، والعميل يلتزم بيها. اللغات اللي فيها garbage collection بتشيل الهم ده عنك.
:::

### المثال التاني: طوابير متعددة (Programs 4.18–4.20)

نفس الحيلة على الـ FIFO queue: `QUEUEinit` بقت **ترجّع** `Q`، وكل عملية بتاخد الـ Q كأول معامل.

```c
Q    QUEUEinit(int maxN);
void QUEUEput(Q, Item);
Item QUEUEget(Q);
```

العميل (Program 4.19) بيحاكي M شبابيك في بنك: كل زبون بيقف في طابور عشوائي، وكل شوية شباك عشوائي بيخدّم زبون. ده كان مستحيل بالـ queue القديم.

```
served  5 from line 0
served  6 from line 2
line 0: 8 12 16 18
line 1: 1 3 4 7 10 17 19
line 2: 9 14
line 3: 0 2 11 13 15
```

## 4.9 ADT من تطبيق: كثيرات الحدود

الكتاب بيختم بمثال أكبر: عايز تحسب `(x+1)^N` وتطبع المعاملات (اللي هي معاملات ذات الحدين، مثلث باسكال). العميل (Program 4.21) بيتكلم بلغة الرياضيات بس:

```c listing="Program 4.21"
t = POLYterm(1, 1); x = POLYadd(t, POLYterm(1, 0));   /* x+1 */
for (i = 1, y = x; i < N; i++) y = POLYmult(x, y);
```

والتنفيذ (4.23) مصفوفة معاملات: `a[i]` = معامل `x^i`. الجمع O(N)، والضرب O(N²) — كل حد في الأول مضروب في كل حد في التاني. ويتحسب بـ Horner في `POLYeval`:

```c listing="Program 4.21"
for (t = 0.0, i = p->N; i >= 0; i--) t = t*x + p->a[i];
```

الكتاب بيذكر بديل: لو كثيرة الحدود «متفرّقة» (زي `x^1000000 + 1`) المصفوفة تهدر مساحة مهولة، وقايمة مترابطة فيها الحدود غير الصفرية بس أحسن. نفس الواجهة، تنفيذين، اختار حسب الاستخدام — دي بالظبط رسالة الفصل.

```
product: +8.0 x^2 +10.0 x^1 +3.0 x^0
eval at 2: 55.0
(x+1)^10 coefficients: 1 10 45 120 210 252 210 120 45 10 1
(x+1)^10 at x=1: 1024 (= 2^10)
```

## 4.10 نظرة عامة

ليه الفصل ده مهم كده؟ لأن باقي الكتاب كله بالشكل ده: **واجهة → عملاء → تنفيذات بتتنافس**.

* الترتيب (الفصل 6–11): واجهة `sort(Item a[], l, r)` و `less`، و10 تنفيذات.
* الـ priority queue (الفصل 9): واجهة insert / delmax، وتنفيذات من القايمة للـ heap للـ binomial queue.
* الـ symbol table (الفصل 12–16): واجهة insert / search، وتنفيذات من المصفوفة للـ BST للهاش للـ B-tree.

:::tip الخلاصة
لما تقابل مشكلة، اكتب الأول الواجهة اللي العميل محتاجها. ساعتها تقدر تقارن الخوارزميات على أرض واحدة، وتبدّل بينها من غير خوف.
:::
