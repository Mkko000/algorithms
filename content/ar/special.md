لحد دلوقتي كل خوارزمية ترتيب شفناها **بتبص على البيانات** وتقرّر: لو a\[i\] أصغر روح يمين، لو لأ روح شمال. الفصل 11 بيسأل سؤال غريب: ينفع نرتّب من غير ما نقرّر أي حاجة بناءً على البيانات؟ يعني سلسلة compare-exchange **ثابتة** مكتوبة من الأول، تشتغل هي هي على أي ملف. الإجابة أيوه، والفايدة كبيرة: حاجة ثابتة كده ينفع تتعمل هاردوير، أو تشتغل على آلاف المعالجات في نفس اللحظة.

:::goal هدف الدرس:
تفهم يعني إيه خوارزمية *nonadaptive*، وتعرف مبدأ الـ 0-1 اللي بيخلّينا نثبت إن شبكة بترتّب، وتكتب Batcher's odd-even merge بالريكيرشن وبالـ shuffle ومن غير ريكيرشن، وترسم شبكة ترتيب وتعدّ الـ comparators والخطوات المتوازية.
:::

## 11.1 Batcher's Odd-Even Mergesort

### Nonadaptive: نفس الخطوات لكل مدخل

خد الـ `compexch(A, B)` اللي استخدمناها من الفصل 6: لو B أصغر من A بدّلهم. خوارزمية مكتوبة كلها كسلسلة compexch على أماكن ثابتة (من غير أي `if` على البيانات) اسمها **nonadaptive** أو straight-line. الـ insertion sort مثلًا **adaptive**: بيقف لما يلاقي العنصر أصغر. الـ selection sort كمان بيختار index حسب البيانات. لكن ممكن نكتب bubble sort كـ nonadaptive: كل اللفّات بكل المقارنات، أيًّا كان.

:::tip ليه نهتم؟
لأن الخطوات الثابتة دي ينفع تتنفّذ **بالتوازي**: أي compexch مالمسوش نفس الخانات يشتغلوا في نفس اللحظة. وده اللي بيعمله الـ GPU والـ SIMD والدوائر المخصّصة.
:::

### الـ perfect shuffle والـ unshuffle (Program 11.1)

Batcher بيعتمد على عمليتين بسيطتين على المصفوفة: **shuffle** زي ما بتفنّط الكوتشينة بالظبط — تقسم الكومة نصّين وتدخّلهم في بعض كارت من هنا وكارت من هنا. و**unshuffle** العكس: اللي في الأماكن الزوجية يروح النص الأول، والفردية النص التاني.

```
shuffle   :  A B C D | E F G H   →   A E B F C G D H
unshuffle :  A E B F C G D H     →   A B C D | E F G H
```

```c
void shuffle(itemType a[], int l, int r)
  { int i, j, m = (l+r)/2;
    for (i = l, j = 0; i <= r; i+=2, j++)
      { aux[i] = a[l+j]; aux[i+1] = a[m+1+j]; }
    for (i = l; i <= r; i++) a[i] = aux[i]; }
void unshuffle(itemType a[], int l, int r)
  { int i, j, m = (l+r)/2;
    for (i = l, j = 0; i <= r; i+=2, j++)
      { aux[l+j] = a[i]; aux[m+1+j] = a[i+1]; }
    for (i = l; i <= r; i++) a[i] = aux[i]; }
```

### الـ merge الريكيرسف (Program 11.2)

عايزين ندمج نصّين مترتبين a\[l..m\] وa\[m+1..r\] (كل واحد حجمه قوة 2). فكرة Batcher:

1. اعمل **unshuffle**: العناصر في الأماكن الزوجية (من النصّين) تروح الشمال، والفردية تروح اليمين.
2. ادمج الشمال لوحده واليمين لوحده **ريكيرسف** (كل واحد فيهم برضه مكوّن من نصّين مترتبين).
3. اعمل **shuffle** عشان ترجّعهم متداخلين.
4. آخر خطوة: compexch على الأزواج (1,2)، (3,4)، (5,6)… بس. وخلاص!

```c
void merge(itemType a[], int l, int m, int r)
  { int i;
    if (r == l+1) compexch(a[l], a[r]);
    if (r < l+2) return;
    unshuffle(a, l, r);
    merge(a, l, (l+m)/2, m);
    merge(a, m+1, (m+1+r)/2, r);
    shuffle(a, l, r);
    for (i = l+1; i < r; i+=2)
      compexch(a[i], a[i+1]); }
```

الخطوة الأخيرة شكلها سحر: إزاي مقارنات بين جيران بس تكفي؟ ده محتاج مبدأ قوي.

### مبدأ الـ 0-1 (Property 11.1)

:::problem
لو برنامج nonadaptive بيرتّب صح **كل** المدخلات اللي فيها أصفار وواحدات بس، يبقى بيرتّب صح **أي** مدخل.
:::

ليه ده مهم؟ لأن الأصفار والواحدات أسهل كتير في التفكير. لـ N = 8 فيه 2⁸ = 256 مدخل من 0 و1 بس — نجرّبهم كلهم ونبقى أثبتنا إن الشبكة سليمة لأي 8 مفاتيح (حتى لو أعداد حقيقية، أو نصوص). البرنامج بتاعنا بيعمل كده بالظبط:

```
all 256 zero-one inputs sorted: yes -> by Property 11.1 it sorts ANY 8 keys
network on 42 7 99 7 3 58 21 0 -> 0 3 7 7 21 42 58 99
```

**فكرة البرهان:** لو الشبكة غلطت في مدخل ما وطلّعت x قبل y مع إن x \> y، حوّل كل مفتاح أصغر من x لـ 0 والباقي لـ 1. الـ compexch بيحافظ على العلاقة دي (الدالة «≥ x» monotone)، فالشبكة هتطلّع 1 قبل 0 — يعني فشلت على مدخل 0-1. يبقى لو نجحت في كل الـ 0-1، عمرها ما تفشل.

### ليه Batcher's merge صح؟ (Property 11.2)

بالمبدأ ده: خد نصّين مترتبين من 0 و1، الأول فيه z₁ صفر والتاني z₂ صفر. بعد الـ unshuffle، الجزء الزوجي فيه ⌈z₁/2⌉+⌈z₂/2⌉ صفر، والفردي ⌊z₁/2⌋+⌊z₂/2⌋. الفرق بينهم **0 أو 1 أو 2**. بعد الدمج الريكيرسف والـ shuffle، الأصفار والواحدات متداخلة، وأقصى غلط ممكن هو «1 0» في مكان واحد بين جارين — والخطوة الأخيرة بتصلّحه بالظبط. ده Property 11.2: **الـ odd-even merge صحيح**.

::figure split-interleave

الرسمة دي (زي Figure 11.9 في الكتاب) هي نفس الـ merge متشاف بطريقة تانية: الملفّين صفين، كل خطوة بتقسم كل صف نصّين وتداخلهم، وبعدين compexch بين صفوف متجاورة بس. الصفوف والأعمدة بيفضلوا مترتبين، ولما يبقى فيه عمود واحد يبقى الملف كله مترتب.

### من غير ريكيرشن (Program 11.3)

لو بصّيت على الـ compexch اللي الـ merge الريكيرسف بيعملها فعلًا (بعد ما تفكّ الـ shuffles)، هتلاقيها نمط منتظم: خطوة أولى بتقارن i مع i+N/2، وبعدين مسافات N/4، N/8… بس بين عناصر في أماكن محددة. Program 11.3 بيكتبها مباشرة:

```c listing="Program 11.3"
void merge(itemType a[], int l, int m, int r)
  { int i, j, k, N = r-l+1;
    for (k = N/2; k > 0; k /= 2)
      for (j = k % (N/2); j+k < N; j += k+k)
        for (i = 0; i < k; i++)
          compexch(a[l+j+i], a[l+j+i+k]); }
```

ومفيش aux ولا shuffles. وده بيبيّن إن الـ shuffle كان مجرد «طريقة كتابة»، مش جزء من الشغل.

## 11.2 Sorting Networks

الطريقة اللطيفة نشوف فيها خوارزمية nonadaptive: **شبكة**. كل خانة في المصفوفة «سلك» أفقي، وكل compexch «comparator» رأسي بين سلكين: البيانات بتعدّي من الشمال لليمين، والأصغر بيطلع على السلك العلوي.

::figure batcher-net

اقرا الشبكة دي من الشمال: أول comparator بيعمل ملفات مترتبة بحجم 2، بعدين شبكة دمج 2×2 بتعمل ملفات بحجم 4، وفي الآخر شبكة دمج 4×4 بتعمل الملف كله. واقراها من اليمين: شبكة دمج بعد نسختين من شبكة الـ 4. هي mergesort بالظبط، بس مكتوبة كشبكة.

::trace batcher

### نعدّ (Property 11.3)

:::problem
شبكات Batcher's odd-even sorting فيها حوالي N(lg N)²/4 comparator، وتقدر تشتغل في (lg N)²/2 خطوة متوازية.
:::

الـ merging network لـ N سلك فيها lg N مرحلة، فالـ sorting network فيها 1 + 2 + … + lg N ≈ (lg N)²/2 مرحلة. كل مرحلة فيها N/2 comparator على الأكتر. برنامجنا بيعدّ:

```
N= 2:   1 comparators,  1 parallel steps
N= 4:   5 comparators,  3 parallel steps
N= 8:  19 comparators,  6 parallel steps
N=16:  63 comparators, 10 parallel steps
N=32: 191 comparators, 15 parallel steps
```

الخطوات المتوازية 1، 3، 6، 10، 15 — دي بالظبط lg N (lg N + 1)/2. والـ comparators: لـ N = 32 الصيغة N(lg N)²/4 = 200، والحقيقي 191. قريب جدًا. يعني الشبكة بتعمل شغل أكتر من mergesort (N lg N = 160) بس بتخلص في 15 خطوة بدل 160.

### البرنامج الأقصر في الكتاب (Program 11.4)

لو حطّيت الـ merge غير الريكيرسف جوه mergesort bottom-up، وشلت الـ comparators اللي بتعدّي حدود الملفات الفرعية، يطلع البرنامج ده — سادجوك بيقول إنه غالبًا «بياخد جايزة أقصر برنامج ترتيب غير تافه شفناه»:

```c listing="Program 11.4"
void batchersort(itemType a[], int l, int r)
  { int i, j, k, p, N = r-l+1;
    for (p = 1; p < N; p += p)
      for (k = p; k > 0; k /= 2)
        for (j = k%p; j+k < N; j += (k+k))
          for (i = 0; i < k; i++)
            if (j+i+k < N)
              if ((j+i)/(p+p) == (j+i+k)/(p+p))
                compexch(a[l+j+i], a[l+j+i+k]); }
```

الشرط `(j+i)/(p+p) == (j+i+k)/(p+p)` معناه «الاتنين في نفس الملف الفرعي بحجم 2p». والشرط `j+i+k < N` بيخلّيه يشتغل حتى لو N مش قوة 2: كأننا بنبني الشبكة لأقرب قوة 2 أكبر، وبنتخيّل إن الأسلاك الزيادة فيها sentinels أكبر من أي مفتاح، فالـ comparators عليها عمرها ما بتبدّل.

### شبكات تانية وتاريخ صغير

* **Bubble sort كشبكة**: N(N−1)/2 comparator و2N−3 خطوة متوازية. فكرة كويسة للتجربة بس بطيئة.
* **Shellsort بزيادات Pratt** (2<sup>p</sup>3<sup>q</sup>): بيتحوّل لشبكة فيها حوالي N(lg N)² comparator، لأن كل h-sort في ملف «شبه مترتب» بيحتاج compexch بين جيران بس.
* **Bitonic sort**: شبكة تانية مشهورة بنفس الحجم تقريبًا، مبنية على ملفات بتطلع وبعدين تنزل.
* **المسألة المفتوحة**: إيه أقل عدد comparators يرتّب N؟ سؤال Bose-Nelson من قبل 1960. Batcher's *merging* networks optimal، لكن الـ sorting networks لأ. سنة 1983، Ajtai وKomlós وSzemerédi (AKS) أثبتوا وجود شبكات بـ O(N log N) comparator — بس الثابت ضخم ومش عملية خالص. فـ Batcher لسه من أحسن الحلول عمليًا.

:::tip الـ butterfly والـ perfect-shuffle machine
لو رتّبت الأسلاك بطريقة تانية، كل الـ comparators تبقى بين أسلاك جنب بعض، والنقلة بين كل خطوة والتانية هي perfect shuffle. يعني آلة متوازية فيها توصيلة shuffle ثابتة بين المعالجات تقدر تنفّذ Batcher كله، وكل اللي «بتبرمجه» هو أنهي أزواج تعمل compexch في كل دورة.
:::

:::oops مش للاستخدام اليومي على CPU
N(lg N)²/4 أكبر من N lg N. على جهاز عادي بمعالج واحد، quicksort أو mergesort هيكسبوا. Batcher بيكسب لما يبقى عندك توازي حقيقي: GPU، SIMD، FPGA، أو لما تحتاج خوارزمية «oblivious» مابتسرّبش معلومات عن البيانات من خلال الـ branches (في الأمن والتشفير).
:::
