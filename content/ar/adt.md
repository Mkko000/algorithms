## 4.1 كائنات مجردة ومجموعات كائنات

**تعريف:** الـ ADT هو نوع بيانات (قيم + عمليات) **ماتوصلّوش إلا من خلال واجهة**. أي برنامج بيستخدمه اسمه «عميل» (client)، والبرنامج اللي بيعرّف العمليات اسمه «تنفيذ» (implementation).

تلات ملفات في C:

* **الواجهة** `STACK.h`: أسماء الدوال وأنواعها بس.
* **التنفيذ** `STACK.c`: الكود الحقيقي (مصفوفة؟ قايمة؟ ماحدش يعرف).
* **العميل** `postfix.c`: بيعمل `#include "STACK.h"` ويستخدم العمليات.

وكمان العناصر نفسها مجردة: سادجوك بيستخدم `Item.h` فيه `typedef int Item;` ومعاه `less` و `eq`. غيّر السطر ده لـ `char *` أو struct، والـ stack يفضل شغال. ده بيتكرر في الكتاب كله — كل خوارزميات الترتيب بتشتغل على `Item`.

معظم الـ ADTs المهمة بتتعامل مع **مجموعات** من الكائنات، وعملياتها الأساسية اتنين: **insert** عنصر جديد، و**delete** عنصر. الفرق بين ADT والتاني هو **أنهي عنصر يتشال**: الـ stack يشيل الأحدث، الـ queue يشيل الأقدم، الـ priority queue يشيل الأكبر، والـ symbol table يشيل اللي مفتاحه كذا.

## 4.2 الـ Pushdown Stack

LIFO: آخر داخل أول خارج. كومة أطباق، أو زرار «Back» في المتصفح.

```c listing="Program 4.1"
/* Program 4.1: STACK.h */
void STACKinit(int);
int  STACKempty(void);
void STACKpush(Item);
Item STACKpop(void);
```

لاحظ: الواجهة مابتقولش «مصفوفة» في أي حتة. حتى `STACKinit(int)` بيدّي أقصى حجم كـ **تلميح** — التنفيذ بالقايمة ممكن يتجاهله.

## 4.3 عملاء الـ Stack

### تقييم postfix (Program 4.2)

التعبير `5 * ( ( ( 9 + 8 ) * ( 4 * 6 ) ) + 7 )` مكتوب postfix: `5 9 8 + 4 6 * * 7 + *`. امشي من الشمال: رقم ← push. عملية ← pop اتنين، احسب، push الناتج.

### تحويل infix لـ postfix (Program 4.3)

الكتاب بياخد تعبير **كامل الأقواس** وبيعمل حاجة بسيطة جدًا: الأرقام تطلع على طول، العمليات تتحط في stack، وكل `)` تطلّع العملية اللي فوق. القوس المفتوح يتجاهل. يعني stack تاني، نوعه حروف.

```c listing="Program 4.3"
if (a[i] == ')')  printf("%c ", STACKpop());
if (a[i] == '+' || a[i] == '*') STACKpush(a[i]);
if (a[i] >= '0' && a[i] <= '9') printf("%c ", a[i]);
```

ملفنا بيمد الفكرة شوية: بيتعامل مع الأولويات (الضرب قبل الجمع) زي خوارزمية Dijkstra المشهورة (shunting-yard)، فـ `5*(((9+8)*(4*6))+7)` بتطلع `598+46**7+*` وتقييمها 2075.

## 4.4 تنفيذين للـ Stack

```c listing="Program 4.4"
/* Program 4.4: array */             /* Program 4.5: linked list */
static Item *s; static int N;         static link head;
void STACKinit(int maxN)              void STACKinit(int maxN)
  { s = malloc(maxN*sizeof(Item));      { head = NULL; }
    N = 0; }
void STACKpush(Item item)             void STACKpush(Item item)
  { s[N++] = item; }                    { head = NEW(item, head); }
Item STACKpop(void)                   Item STACKpop(void)
  { return s[--N]; }                    { Item item = head->item; link t = head->next;
                                          free(head); head = t; return item; }
```

<tr><th></th><th>مصفوفة</th><th>قايمة مترابطة</th></tr>
<tr><td>push / pop</td><td>O(1)، أسرع عمليًا</td><td>O(1)، بس malloc/free كل مرة</td></tr>
<tr><td>المساحة</td><td>الحجم الأقصى محجوز من الأول</td><td>على قد العناصر + مؤشر لكل واحد</td></tr>
<tr><td>العيب</td><td>لازم تعرف الحد الأقصى (أو تكبّر بالمضاعفة — الدرس 04)</td><td>مساحة زيادة لكل عنصر</td></tr>
</table>

الحلو إن العميل (postfix) **ماتغيّرش ولا سطر** بين التنفيذين. ملفنا فيه الاتنين جنب بعض.

:::oops اتنين أخطاء بنسكت عنهم في الأمثلة
pop من stack فاضي (underflow) و push على مصفوفة مليانة (overflow). الكتاب بيقول صراحة إنه بيسيبهم للتبسيط. في كود حقيقي: إما تفحص وترجّع error، أو توثّق إن العميل مسؤول.
:::
