## 1.2 المشكلة بالظبط

المدخل: سلسلة أزواج `p-q`، كل زوج معناه «p متوصل بـ q». التوصيل علاقة **تكافؤ**:

* **انعكاسية:** p متوصل بنفسه.
* **تماثلية:** لو p بـ q يبقى q بـ p.
* **متعدية:** لو p بـ q و q بـ r يبقى p بـ r. (دي اللي بتخلّي المشكلة مش تافهة.)

المطلوب: لكل زوج جديد، اطبعه **بس** لو مش مستنتج من الأزواج اللي قبله. يعني بنبني «شجرة امتداد» للمكوّنات من غير ما نحتاج نعرف المسار نفسه — بس هل في مسار ولا لأ. ده أقل من اللي برامج الجرافات بتحسبه، وعشان كده ممكن نحلّه أسرع بكتير.

تطبيقات: شبكات (هل الجهازين على نفس الشبكة؟)، دوائر كهربية (نقط متوصلة بسلك)، المترجمات (إعلانات `EQUIVALENCE` في فورتران: متغيرين يشيروا لنفس الذاكرة)، والصور (البكسلات المتلاصقة بنفس اللون = منطقة واحدة).

بنفصّل المشكلة لعمليتين مجرّدتين: **find** (المكوّن بتاع العنصر ده إيه؟) و **union** (ادمج مكوّنين). أي خوارزمية = طريقة لتمثيل المكوّنات تخلّي العمليتين دول رخاص.

## 1.3 الخوارزميات

### 1) Quick-find — Program 1.1

مصفوفة `id[]`: كل عنصر له «اسم مكوّن». p و q متوصلين ⟺ `id[p] == id[q]`. في البداية `id[i] = i`.

```c listing="Program 1.1"
/* Program 1.1 — الفكرة */
if (id[p] == id[q]) continue;          /* already connected */
for (t = id[p], i = 0; i < N; i++)
    if (id[i] == t) id[i] = id[q];     /* rename the whole component */
```

الـ find مقارنة واحدة. الـ union بيلف على **كل** المصفوفة. **Property 1.1:** M عملية union على N عنصر = حوالي **M·N** تعليمة. لـ N=10⁹ و M=10¹⁰ ده 10¹⁹ — سنين.

::figure uf-quickfind

### 2) Quick-union — Program 1.2

نغيّر المعنى: `id[i]` بقى **الأب** بتاع i. كل مكوّن شجرة، والجذر هو اسمه (العنصر اللي `id[i]==i`). الـ find = اطلع لحد الجذر. الـ union = اربط جذر بجذر (سطر واحد!).

```c listing="Program 1.2"
for (i = p; i != id[i]; i = id[i]) ;
for (j = q; j != id[j]; j = id[j]) ;
if (i == j) continue;
id[i] = j;                             /* one root under the other */
```

الـ union بقى رخيص، بس الـ find بقى بيمشي طول الشجرة. **Property 1.2:** لو M \> N ممكن ناخد أكتر من **M·N/2**. إزاي؟ الأزواج `1-0, 2-1, 3-2, …` بتعمل سلسلة طولها N زي المكرونة، وكل find بعدها بيمشي السلسلة كلها.

::figure uf-qu-bad

### 3) Weighted quick-union — Program 1.3

الحل العبقري البسيط: احتفظ بحجم كل شجرة في `sz[]`، و**اربط الأصغر تحت الأكبر**.

```c listing="Program 1.3"
if (sz[i] < sz[j]) { id[i] = j; sz[j] += sz[i]; }
else               { id[j] = i; sz[i] += sz[j]; }
```

**Property 1.3:** بنتبع على الأكثر **2 lg N** مؤشر عشان نعرف اتنين متوصلين ولا لأ. الدليل حلو: عمق عقدة بيزيد 1 بس لما شجرتها (الأصغر) تتعلق تحت شجرة أكبر منها أو قدّها — يعني حجم شجرتها **على الأقل بيتضاعف**. الحجم ماينفعش يتضاعف أكتر من lg N مرة قبل ما يوصل N. خلصت.

::figure uf-weighted

### 4) Path compression — Program 1.4 والأنواع التانية

وإحنا طالعين للجذر، ليه مانخلّيش العقد اللي عدّينا عليها تشاور على الجذر على طول؟ كده الـ find الجاية أقصر. في كذا طريقة:

* **Full path compression:** لفّة تانية بعد ما توصل للجذر، وكل عقدة على المسار تشاور عليه مباشرة. أقوى تسطيح، بس لفتين.
* **Path halving (Program 1.4):** في نفس اللفّة، كل عقدة تشاور على جدّها: `id[i] = id[id[i]]`. سطر واحد، تأثير تقريبًا زي الكامل.
* **Path splitting:** زي halving بس لكل عقدة مش عقدة كل اتنين (تمرين في الكتاب).

```c listing="Program 1.4"
/* halving — Program 1.4 */
for (i = p; i != id[i]; i = id[i]) id[i] = id[id[i]];

/* full compression — two passes */
r = p; while (r != id[r]) r = id[r];
while (p != r) { next = id[p]; id[p] = r; p = next; }
```

مع الـ weighting، التكلفة لكل عملية بتبقى عمليًا ثابتة: النظرية (Tarjan) بتقول قريبة من α(N)، معكوس دالة أكرمان، اللي هو ≤ 5 لأي N في الكون. سادجوك بيقول بصراحة: مفيش خوارزمية خطية بالظبط معروفة، بس ده «كويس كفاية» بفرق ضئيل.

::trace union-find

:::tip مثال يدوي
ابدأ بـ 0..9. الأزواج: 3-4 ، 4-9 ، 8-0 ، 2-3 ، 5-6 ، 2-9 (متوصلين خلاص — مايتطبعش)، 5-9 ، 7-3 ، 4-8 ، 5-6 (مكرر)، 0-2 (متوصلين)، 6-1. الأزواج اللي اتطبعت 9 بس لـ 10 عناصر = مكوّن واحد. جرّبها في الأداة فوق وشوف الشجرة.
:::
