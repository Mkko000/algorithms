### إزاي تحلّها بإيدك: telescoping

خد الرابعة، وافرض N = 2ⁿ عشان القسمة تبقى نضيفة:

```
C(2ⁿ) = 2 C(2ⁿ⁻¹) + 2ⁿ
اقسم على 2ⁿ:   C(2ⁿ)/2ⁿ = C(2ⁿ⁻¹)/2ⁿ⁻¹ + 1
                         = C(2ⁿ⁻²)/2ⁿ⁻² + 1 + 1
                         = …  = n
يعني C(N) = N lg N
```

الحيلة: اقسم على حاجة تخلّي الطرفين «نفس الشكل» بفرق ثابت، وبعدين افرد السلسلة. الأولى أسهل: C<sub>N</sub> = N + (N−1) + … + 1 = N(N+1)/2. والتالتة: N + N/2 + N/4 + … = 2N (متسلسلة هندسية).

ولو N مش قوة 2؟ الحل بيفضل قريب جدًا (الفرق حدود صغيرة). الأداة تحت بتحسبها بالظبط عشان تتأكد بعينك.

## 2.6 أمثلة تحليل حقيقية: البحث

**Property 2.1 (بحث تتابعي):** لو بندوّر في N رقم: البحث الفاشل بيفحص **N** دايمًا، والناجح حوالي **N/2** في المتوسط (لو كل مفتاح احتماله متساوي إنه يكون المطلوب: (1+2+…+N)/N = (N+1)/2).

**Property 2.2:** لو الجدول مترتب، البحث الفاشل يقدر يقف أول ما يعدّي المفتاح — فبيبقى N/2 في المتوسط بدل N. تحسين بس بثابت 2.

**Property 2.3 (بحث ثنائي):** مابيفحصش أكتر من **⌊lg N⌋ + 1** رقم أبدًا. الدليل هو المعادلة التانية بالظبط: كل خطوة بتشيل نص المساحة.

```c
int search(int a[], int v, int l, int r)      /* Program 2.2 */
  { while (r >= l)
      { int m = (l+r)/2;
        if (v == a[m]) return m;
        if (v < a[m]) r = m-1; else l = m+1;
      }
    return -1;
  }
```

الترجمة العملية: مليون مفتاح × مليون بحث. تتابعي ≈ 5·10¹¹ مقارنة (ساعات). ثنائي ≈ 2·10⁷ (أقل من ثانية). وده تمن ترتيب الجدول مرة واحدة الأول.

## 2.7 ضمانات، توقّعات، وحدود

### أسوأ حالة = ضمان

لو أثبتنا إن الخوارزمية عمرها ما تعدّي f(N)، ده **ضمان** مهما كان المدخل — حتى لو عدو بيختاره. مفيد جدًا للأنظمة اللي مايتحملش فيها مفاجآت (طيارات، بورصة).

### متوسط الحالة = توقّع

بيفترض نموذج للمدخلات (مثلًا ترتيب عشوائي). لو البيانات الحقيقية مش زي النموذج، التوقّع ممكن يطلع غلط. quicksort متوسطه ممتاز بس على ملف مترتب (حاجة بتحصل كتير!) ممكن يبقى N².

### الحل: خلّي العشوائية جوّه الخوارزمية (randomized)

بدل ما نتمنى إن المدخل عشوائي، الخوارزمية نفسها ترمي عملة (pivot عشوائي، randomized BST، skip list). ساعتها «المتوسط» بقى على اختيارات الخوارزمية مش على المدخل، ومفيش مدخل شرير بعينه. احتمال الأداء الوحش بيبقى ضئيل جدًا (أقل من احتمال إن الجهاز نفسه يعطل في نص الشغل).

### Amortized: عملية غالية بس الإجمالي رخيص

مثال: مصفوفة بتتضاعف لما تتملي. push معيّن ممكن ينسخ مليون عنصر! بس على N push، إجمالي النسخ ≤ 2N. يعني **O(1) لكل عملية في المتوسط على التسلسل** — ودي مش «متوسط احتمالي»، دي ضمان على أي تسلسل. نفس الفكرة في path compression و splay trees.

```
$ ./recurrences    (آخر جزء)
  1000000 pushes ->  1048575 element copies  (1.05 per push)
```

### الحدود

التحليل له حدود صريحة: الثوابت ممكن تكون كبيرة، المسائل الرياضية ساعات مفتوحة (shellsort لسه مالوش تحليل كامل)، والنموذج ممكن ماينطبقش. عشان كده الكتاب بيجمع دايمًا بين التحليل والتجربة.
