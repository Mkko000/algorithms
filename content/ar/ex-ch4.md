### تمرين 4.6 و4.31: نفس الـ sequence على stack وعلى queue

:::problem
الحرف معناه push والنجمة معناها pop في السلسلة `E A S * Y * Q U E * * * S T * * * I O * N * * *`. إيه القيم اللي هترجع من الـ pops؟ (4.31) نفس السؤال لو كانت FIFO queue (الحرف put والنجمة get).
:::

:::think
في الـ stack، كل نجمة بتطلّع **آخر** حرف دخل ولسه موجود. وفي الـ queue بتطلّع **أقدم** حرف. وفيه ملاحظة بتوفّر وقت: في الـ queue الترتيب اللي بيطلع هو نفس ترتيب الدخول بالظبط، أيًّا كانت أماكن النجوم (طالما مفيش get من queue فاضية). فإجابة 4.31 هي الحروف بالترتيب!
:::

:::solution
```
4.6  stack pops: S Y E U Q T S A O N I E
4.31 queue gets: E A S Y Q U E S T I O N
```

تتبّع أول جزء في الـ stack: E A S ← `*` يطلّع S. Y ← `*` يطلّع Y. Q U E ← `* * *` تطلّع E U Q. وفاضل في الـ stack: E A. S T ← `* * *` تطلّع T S A. وهكذا. والـ queue بتطلّع «EASYQUESTION». السؤال كان معمول عشان يطلّع كلمة.
:::

### تمرين 4.7 و4.8: ترتيب ممكن ولا مستحيل؟

:::problem
بنفس اصطلاح 4.6، حط نجوم في `E A S Y` بحيث الـ pops ترجّع (i) E A S Y، (ii) Y S A E، (iii) A S Y E، (iv) A Y E S، أو أثبت إن مفيش طريقة. (4.8) اديني خوارزمية تحدد لأي سلسلتين: ينفع نحط نجوم في الأولى تخلّيها تطلّع التانية؟
:::

:::think
مفيش اختيار حقيقي هنا. لو الحرف اللي على الـ top هو الحرف اللي محتاجه دلوقتي، لازم تعمل pop (لو أجّلته، هيتدفن تحت حروف تانية ومش هيطلع قبلهم). ولو مش هو، لازم تعمل push للحرف الجاي. يعني **greedy**: ولو الـ input خلص والـ top مش اللي محتاجه، يبقى مستحيل. ده نفسه حل 4.8، وفي وقت O(N).
:::

:::solution
```
4.7  EASY -> EASY : E*A*S*Y*
4.7  EASY -> YSAE : EASY****
4.7  EASY -> ASYE : EA*S*Y**
4.7  EASY -> AYES : impossible
```

ليه (iv) مستحيلة؟ عشان A تطلع الأول لازم E تبقى تحت A. بعد كده عشان Y تطلع، لازم S تدخل الأول (S قبل Y في الـ input)، فالـ stack يبقى E S Y. الـ Y تطلع، والـ top بقى S. بس إحنا محتاجين E، وE تحت S. ∎ والقاعدة العامة: لو a وb وc داخلين بالترتيب ده، مستحيل يطلعوا c بعدين a بعدين b (النمط «3-1-2» ممنوع). وفي (iv): Y وE وS = 4 و1 و3، وده نفس النمط بالظبط.
:::

### تمرين 4.34 و4.35: الـ deque

:::problem
الحرف الكبير معناه put في الأول، والصغير put في الآخر، و`+` get من الأول، و`*` get من الآخر، في `E A s + Y + Q U E * * + s t + * + I O * n + + *`. إيه اللي بيرجع؟ (4.35) حط + و\* في `E a s Y` عشان يطلع (i) E s a Y، (ii) Y a s E، (iii) a Y s E، (iv) a s Y E، أو أثبت إنه مستحيل.
:::

:::think
للتتبّع: اكتب الـ deque كصف أفقي، واعرف كل حرف رايح أنهي طرف. وللـ 4.35 الـ greedy مش كفاية، لأن فيه دلوقتي اختيارين للـ get (من الأول أو من الآخر). فبنعمل **بحث** (DFS): في كل خطوة إما put للحرف الجاي، أو get من أي طرف لو هيطلّع الحرف المطلوب بالظبط. والشرط ده الأخير بيقطع تقريبًا كل الفروع، فالبحث سريع جدًا عمليًا. وده حل 4.36.
:::

:::solution
```
4.34 deque gets: A Y s E E U t Q s O I n
4.35 EasY -> EsaY : E+as*+Y+
4.35 EasY -> YasE : impossible
4.35 EasY -> aYsE : Ea*sY+*+
4.35 EasY -> asYE : Ea*s*Y++
```

ليه (ii) مستحيلة؟ Y آخر حرف في الـ input، فعشان تطلع الأول لازم E وa وs يكونوا جوه. والـ deque ساعتها E a s (E في الأول، وa وs اتحطوا في الآخر). بعد Y محتاجين a، وa في النص بين E وs، وإنت مش بتقدر توصل غير للأطراف. ∎
:::

### تمرين 4.9 و4.10: postfix

:::problem
(4.9) حوّل `( 5 * ( ( 9 * 8 ) + ( 7 * ( 4 + 6 ) ) ) )` لـ postfix. (4.10) زي Figure 4.2، وريني محتوى الـ stack وProgram 4.2 بيحسب `5 9 * 8 7 4 6 + * 2 1 3 * + * + *`.
:::

:::think
Program 4.3 بسيط جدًا: الرقم يطلع على طول، والـ operator يدخل stack، وكل `)` تطلّع operator. يعني الـ operator بيطلع لما قوسه يتقفل. وفي التقييم: الرقم push، والـ operator ياخد آخر اتنين ويرجّع الناتج.
:::

:::solution
```
4.9  postfix: 5 9 8 * 7 4 6 + * + *   = 710
4.10   5 : 5            *  : 45 8 70
       9 : 5 9          2  : 45 8 70 2
       * : 45           1  : 45 8 70 2 1
       8 : 45 8         3  : 45 8 70 2 1 3
       7 : 45 8 7       *  : 45 8 70 2 3
       4 : 45 8 7 4     +  : 45 8 70 5
       6 : 45 8 7 4 6   *  : 45 8 350
       + : 45 8 7 10    +  : 45 358
                        *  : 16110
```

لاحظ إن الـ stack وصل لعمق 6 بس. وأقصى عمق هو أقصى عدد «نتايج مستنية» في نفس الوقت.
:::

### تمرين 4.11، 4.12 و4.16: طرح وقسمة وsqrt، باستاكّين

:::problem
زوّد `-` و`/` (4.11)، وبعدين unary minus و`$` (جذر تربيعي) بـ floating point (4.12). المثال `(-(-1) + $((-1) * (-1)-(4 * (-1))))/2` لازم يطبع **1.618034**. (4.16) ادمج Program 4.2 و4.3 في module واحد فيه stack أرقام وstack operators.
:::

:::think
المثال مش fully parenthesized، فـ Program 4.3 لوحده مش كفاية. محتاج **precedence**: قبل ما تحط operator، طبّق كل اللي في الـ stack وأولويته ≥ أولويته. والحتة الصعبة: إزاي تفرّق بين `-` الطرح و`-` السالب؟ بص على اللي قبلها: لو كنت مستني operand (في الأول، أو بعد `(` أو operator)، يبقى unary. وخزّنها كرمز تاني (`n`) بأولوية أعلى.
:::

:::solution
```c
if (c == '-' && expectOperand) c = 'n';         /* unary minus */
if (c == 'n' || c == '$') { ops[no++] = c; continue; }
while (no && ops[no-1] != '(' && prec(ops[no-1]) >= prec(c)) apply();
ops[no++] = c;
```

```
4.11 (8 - 2) / 3 - 1 = 1
4.12 (-(-1) + $((-1) * (-1) - (4 * (-1)))) / 2 = 1.618034
4.16 5 * (((9 + 8) * (4 * 6)) + 7) = 2075
```

1\.618034 هي النسبة الذهبية (1+√5)/2، والمثال معمول عشان يطلّعها. وشرط `>=` هو اللي بيخلّي `8 - 2 - 1` تتحسب من الشمال لليمين: 5، مش 7.
:::

### تمرين 4.24 و4.19: two stacks في array واحدة

:::problem
اعمل ADT بيدّي الـ client اتنين pushdown stacks في array واحدة: واحد بيبدأ من أول الـ array، والتاني من آخرها. (4.19) وبدّل «test if empty» بـ `count`.
:::

:::think
stack 0 بيكبر لليمين من 0، وstack 1 بيكبر للشمال من MAX. يتملوا بس لما الاتنين يتقابلوا (`top0 == top1`). يعني لو واحد كبير والتاني صغير، المساحة كلها مستغلّة. وده مستحيل لو قسمت الـ array نصّين.
:::

:::solution
```c
int push(int s, int v)
  { if (top0 == top1) return 0;                  /* full */
    if (s == 0) A[top0++] = v; else A[--top1] = v;
    return 1; }
int count(int s) { return s == 0 ? top0 : MAX - top1; }
```

```
4.24 pushed 8 of 10 into an array of 8: count0=5 count1=3 (full)
     pop0=4 pop1=102 -> count0=4 count1=2
```
:::

### تمرين 4.28 و4.42: عدد الـ nodes المتوصّلة، والـ random queue

:::problem
(4.28) عدّل الـ union-find ADT عشان يرجّع عدد الـ nodes المتوصّلة بـ node معيّنة. (4.42) ابني random-queue ADT بـ array، الـ get فيه بيشيل item عشوائي، وكل عملية في وقت ثابت.
:::

:::think
4\.28: الـ weighted union بيحتفظ أصلًا بـ `sz[root]`! فالإجابة `sz[find(p)]` ببلاش. 4.42: الشيل من نص array بيكلّف O(N) لو حرّكت اللي بعده. الحيلة: الترتيب مش مهم أصلًا في random queue، فبدّل العنصر المختار بالأخير، وشيل الأخير.
:::

:::solution
```c
int compsize(int p) { return sz[find(p)]; }
int rqget(void) { int i = rand() % n, v = q[i]; q[i] = q[--n]; return v; }
```

```
4.28 after the pairs of Figure 1.1: size(0)=10 size(7)=10 size(10)=1
4.42 first get from a random queue of 0..4 (100000 trials): 0:20135 1:20086 2:19998 3:19815 4:19966
```

كل قيمة طلعت حوالي 20%، يعني الاختيار منتظم فعلًا.
:::

### تمرين 4.48 و4.49: stack من غير تكرار

:::problem
عدّل الـ array stack عشان مايسمحش بالتكرار: (4.48) بسياسة «تجاهل الجديد»، و(4.49) بسياسة «انسى القديم». بـ brute force.
:::

:::think
الاتنين بيدوّروا على القيمة في الـ stack (O(N)). الفرق: «تجاهل الجديد» لو لقاها مايعملش حاجة. و«انسى القديم» يشيل النسخة القديمة من مكانها (ويزحّلق اللي فوقها) ويحط الجديدة على الـ top. يعني التانية بتخلّي آخر استخدام هو اللي يحدد المكان، وده بالظبط سلوك الـ LRU cache.
:::

:::solution
```
4.48 ignore new, push 1 2 3 2 4 1 5: 1 2 3 4 5   (top = right)
4.49 forget old, push 1 2 3 2 4 1 5: 3 2 4 1 5   (top = right)
```

وفي 4.51 الكتاب بيطلب نسخة بـ O(1) لـ items من 0 لـ M−1. الفكرة: array `where[v]` فيه مكان v في الـ stack، أو −1 لو مش موجود. ده key-indexed تاني.
:::
