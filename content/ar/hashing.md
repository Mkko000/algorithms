فاكر الـ key-indexed search؟ لو المفاتيح أرقام صغيرة، المفتاح نفسه هو مكانه في المصفوفة، والبحث عملية واحدة. الـ hashing بيعمّم الفكرة دي لأي مفتاح: **حوّل المفتاح لرقم صغير** (بين 0 وM−1)، واستخدمه index. المشكلة الوحيدة: مفتاحين مختلفين ممكن يتحوّلوا لنفس الرقم — ودي اسمها **collision**. والفصل كله عن حاجتين: إزاي نعمل دالة تحويل كويسة، وإزاي نتعامل مع الـ collisions.

:::goal هدف الدرس:
تكتب hash functions صح لأرقام صحيحة وكسور ونصوص، تفهم ليه M لازم يبقى prime في الـ modular hashing، تعرف إيه الـ universal hashing، وتكتب separate chaining وتفهم تكلفته بالأرقام.
:::

## الـ trade-off الأساسي

الـ hashing مثال كلاسيكي على trade-off بين الوقت والمساحة. لو معاك ذاكرة لانهائية، اعمل مصفوفة بحجم كل المفاتيح الممكنة (key-indexed). لو معاكش وقت خالص، sequential search بأقل ذاكرة. الـ hashing في النص: بذاكرة معقولة ووقت معقول، بيدّي search وinsert في **وقت ثابت في المتوسط**. والتمن: مفيش ترتيب. يعني select وsort وrange search مش متاحين بكفاءة.

## 14.1 Hash Functions

الدالة المثالية: سريعة الحساب، وبتوزّع المفاتيح «كأنها عشوائية» على M خانة. وكل نوع مفتاح ليه طريقته:

### كسور بين 0 و1

اضرب في M وخد الجزء الصحيح: `h = (int)(k * M)`. لو المفاتيح منتظمة التوزيع، النتيجة منتظمة. ولو المفاتيح بين s وt: حوّلها الأول لـ (k−s)/(t−s).

### أرقام صحيحة: الـ modular hashing

`h = k % M`. أبسط حاجة. بس اختيار M مهم جدًا: لو M قوة 2 (زي 1024)، الـ mod بيرجّع آخر 10 بتات بس — وأي مفاتيح بتشترك في آخر البتات (كلها زوجي، أو كلها مضاعفات 64) هتتكوّم في نفس الخانات.

```
integer keys that are multiples of 64 (N=10000):
  k mod 1024 (power of 2)                longest bucket  625, empty 1008, chi2/M 615.23 (~1 is ideal)
  k mod 1021 (prime)                     longest bucket   10, empty    0, chi2/M 0.02 (~1 is ideal)
```

نفس المفاتيح بالظبط. M = 1024: 1008 خانة فاضية وواحدة فيها 625! M = 1021 (prime قريب): توزيع ممتاز. القاعدة: **خلّي M عدد أولي**، ويفضّل مايبقاش قريب من قوة 2.

:::tip الـ multiplicative hashing
بديل تاني: اضرب المفتاح في ثابت كسري (زي 0.618… = النسبة الذهبية) وخد الجزء الكسري واضربه في M. ده بيشتغل كويس حتى لو M قوة 2، وكان شائع على الأجهزة اللي الـ mod فيها غالي.
:::

### نصوص: طريقة Horner (Program 14.1)

نص زي «averylongkey» = رقم كبير جدًا مكتوب بأساس 128 (كل حرف رقم). مش هينفع نحسبه كله (overflow). بس طريقة Horner بتسمح نعمل mod في كل خطوة:

```c listing="Program 14.1"
int hash(char *v, int M)
  { int h = 0, a = 127;
    for (; *v != '\0'; v++)
      h = (a*h + *v) % M;
    return h; }
```

لأن (a·x + c) mod M = (a·(x mod M) + c) mod M، النتيجة هي هي كأننا حسبنا الرقم كله. والـ a = 127 بدل 128 عشان لو M قوة 2 أو فيه علاقة بـ 128، مانبوّظش التوزيع.

```
string keys "key0".."key9999":
  Horner a=127, M=1024 (power of 2!)     longest bucket   79, empty  576, chi2/M 41.97 (~1 is ideal)
  Horner a=127, M=1021 (prime)           longest bucket   18, empty    0, chi2/M 0.88 (~1 is ideal)
  BAD: sum of characters mod 1021        longest bucket  615, empty  930, chi2/M 394.62 (~1 is ideal)
```

شوف «مجموع الحروف»: فكرة بتيجي في بال ناس كتير، وهي كارثة. «key12» و«key21» و«key30» ليهم نفس المجموع، وأي مجموع صغير مايتعدّاش بضع مئات أصلًا.

### Universal hashing (Program 14.2)

أي دالة ثابتة، فيه مجموعة مفاتيح «وحشة» ليها (ممكن حد يختارها قصد عشان يعمل attack). الحل: **عشوائية**. بدل a ثابت، غيّره في كل حرف بطريقة شبه عشوائية:

```c listing="Program 14.2"
int hashU(char *v, int M)
  { int h, a = 31415, b = 27183;
    for (h = 0; *v != '\0'; v++, a = a*b % (M-1))
      h = (a*h + *v) % M;
    return (h < 0) ? (h + M) : h; }
```

الفكرة النظرية: لو اخترنا الدالة عشوائيًا من «عيلة» مناسبة، احتمال إن مفتاحين بعينهم يصطدموا ≈ 1/M، **لأي** مفتاحين. يعني مفيش input وحش في المتوسط على الاختيارات.

```
  universal hashU, M=1021                longest bucket   29, empty  156, chi2/M 5.62 (~1 is ideal)
```

بصراحة: على المفاتيح المنتظمة دي بالذات Horner العادي مع prime كان أحسن. الـ universal مش هدفه يكسب على input واحد، هدفه إنه **مايخسرش جامد على أي input**.

## 14.2 Separate Chaining

أبسط حل للـ collisions: كل خانة في الجدول **قايمة متصلة** بكل المفاتيح اللي اتحوّلت لها. الـ insert: احسب h وحط في أول القايمة. الـ search: احسب h ودوّر sequential في القايمة دي بس.

::figure chaining

```c
static link *heads, z;
static int N, M;
void STinit(int max)
  { int i;
    N = 0; M = max/5;
    heads = malloc(M*sizeof(link));
    z = NEW(NULLitem, NULL);
    for (i = 0; i < M; i++) heads[i] = z; }
Item STsearch(Key v)
  { return searchR(heads[hash(v, M)], v); }
void STinsert(Item item)
  { int i = hash(key(item), M);
    heads[i] = NEW(item, heads[i]); N++; }
void STdelete(Item item)
  { int i = hash(key(item), M);
    heads[i] = deleteR(heads[i], item); }
```

(Program 14.3. الـ M = max/5 يعني متوسط طول القايمة حوالي 5.)

:::problem
الـ separate chaining بيقلّل عدد مقارنات الـ sequential search بمعامل **M** (في المتوسط)، باستخدام ذاكرة زيادة لـ M لينك.
:::

يعني متوسط طول القايمة N/M، والبحث الناجح حوالي (N/M)/2، والفاشل N/M (أو النص لو القوايم مترتبة).

:::problem
في جدول separate chaining فيه M قايمة وN مفتاح، احتمال إن طول كل قايمة يبقى في حدود معامل ثابت صغير من N/M قريب جدًا من 1.
:::

يعني مش بس المتوسط كويس — مستحيل عمليًا إن قايمة واحدة تبقى طويلة جدًا (لو الـ hash function كويسة). ده من الـ binomial distribution: احتمال قايمة فيها أكتر من t·α عنصر بيقل بشكل أُسّي مع t. (مثال الكتاب: لو متوسط طول القوايم 20، احتمال إننا نقع على قايمة فيها أكتر من 40 عنصر أقل من (e/2)<sup>20</sup>e<sup>−20</sup> ≈ 0.0000016.) ومن نفس التحليل (مسألة «الكور والصناديق» الكلاسيكية): نسبة القوايم الفاضية حوالي e<sup>−α</sup>، وأول collision بيحصل بعد حوالي √(πM/2) مفتاح بس — يعني الـ collisions مش استثناء، دي حاجة أكيدة حتى في جدول شبه فاضي (مفارقة عيد الميلاد: لـ M = 365، حوالي 24 شخص). والعكس، عشان كل القوايم يبقى فيها عنصر واحد على الأقل، محتاج حوالي M·H<sub>M</sub> ≈ M ln M مفتاح (مسألة جامع الكوبونات).

```
search   -> bucket 0, value 0
hash     -> bucket 4, value 10
table    -> bucket 6, value 20
...
N=7 M=10 avg list length ~ 0.7
```

### اختيار M

بما إن القوايم بتكبر بالراحة (مفيش «امتلاء»)، الـ separate chaining مابيقعش لو N زاد عن المتوقع، بس بيبطأ تدريجيًا. القاعدة العملية: خلّي M حوالي N/5 لـ N/10 — قوايم قصيرة وذاكرة معقولة. ولو مش عارف N من الأول، استخدم جدول بيكبر (الدرس الجاي).

:::tip قوايم مترتبة؟
لو خلّيت كل قايمة مترتبة، الـ search miss بيقف بدري (نص التكلفة). بس الـ insert بقى أغلى. مع قوايم طولها 5، مش فارقة كتير. الأهم: hash function كويسة.
:::
