كل طرق البحث اللي فاتت (BST، red-black، hashing) بتعامل المفتاح كـ «كتلة»: يا تقارنه كله بمفتاح تاني، يا تحسب عليه hash. الفصل 15 بيعمل زي الـ radix sort في الفصل 10: **بيبص على المفتاح حتة حتة** (بت بت، أو حرف حرف). والنتيجة: بحث وقته مربوط بطول المفتاح مش بعدد المفاتيح، ومفيش «worst case كارثي» زي الـ BST مع المفاتيح المترتبة.

:::goal هدف الدرس:
تكتب digital search tree وتفهم ليه طولها محدود بعدد البتات، تكتب trie ثنائي وتفهم ليه شكله مابيعتمدش على ترتيب الإدخال، وتعرف تكلفته بالأرقام (lg N بت، 1.44N عقدة).
:::

## الفكرة والكود الثنائي

هنستخدم نفس `digit(v, w)` بتاعة الفصل 10: البت رقم w في المفتاح v (من الشمال). وللأمثلة هنستخدم أكواد 5 بت للحروف زي الكتاب: A = 00001، B = 00010، … S = 10011، X = 11000.

## 15.1 Digital Search Trees

أبسط تعديل ممكن على الـ BST: بدل ما تقارن المفتاح بمفتاح العقدة عشان تختار شمال ولا يمين، **بص على البت**: في المستوى w، لو البت رقم w في مفتاح البحث 0 روح شمال، لو 1 روح يمين. وكل عقدة لسه فيها مفتاح واحد بنقارنه بالمساواة.

```c
Item searchR(link h, Key v, int w)
  { Key t = key(h->item);
    if (h == z) return NULLitem;
    if eq(v, t) return h->item;
    if (digit(v, w) == 0)
         return searchR(h->l, v, w+1);
    else return searchR(h->r, v, w+1); }
```

والـ insert نفس البحث + تعليق العقدة الجديدة (Program 15.1).

::figure dst

خلّي بالك من حاجة غريبة: الـ DST **مش** BST. المفاتيح اللي شمال عقدة مش لازم تكون أصغر منها — كل اللي مضمون إن كل المفاتيح في الشجرة الشمال (تحت مستوى w) بتشترك في نفس أول w بت، والبت اللي بعده 0. يعني الـ DST مابتعرفش تعمل sort أو select بسهولة.

:::problem
البحث أو الإضافة في DST بيحتاج حوالي **lg N** مقارنة في المتوسط، وحوالي **2 lg N** في أسوأ حالة، في شجرة مبنية من N مفتاح عشوائي. وعدد المقارنات **عمره ما يزيد** عن عدد البتات في المفتاح.
:::

```
DST, 65536 keys inserted in increasing order: height 16 (BST would be 65535)
search hits: avg 15.2, max 17 compares (lg N = 16, key bits = 32)
root key = 0 = the FIRST key inserted (a BST-like shape, but branching on bits)
```

نفس الـ input اللي بيقتل الـ BST (مفاتيح مترتبة): ارتفاع 16 بدل 65535! لأن الشجرة بتتفرّع على البتات، والمفاتيح المترتبة بتملا كل الاحتمالات بانتظام. أي DST على مفاتيح 32 بت ارتفاعها ≤ 32 مهما حصل.

## 15.2 Tries

الاسم جاي من re**trie**val (وبيتنطق «try» عشان يتفرّق عن tree). الفكرة: ماتحطّش مفاتيح في العقد الداخلية خالص. العقد الداخلية مجرد «مفترق طرق»، والمفاتيح في الأوراق.

:::problem
الـ trie هو binary tree المفاتيح فيه في الأوراق، ومتعرّف ريكيرسف: trie لمجموعة فاضية = لينك فاضي؛ trie لمفتاح واحد = ورقة فيها المفتاح؛ وtrie لأكتر من مفتاح = عقدة داخلية، الشمال فيها trie للمفاتيح اللي أول بت فيها 0، واليمين trie للي أول بت فيها 1 (والبت الأول متشال من الاعتبار في الشجر الفرعي).
:::

### البحث والإضافة (Programs 15.2–15.3)

البحث: انزل حسب البتات لحد ما توصل لورقة، وقارن المفتاح **مرة واحدة** هناك. الإضافة: ابحث؛ لو وصلت لينك فاضي حط ورقة. لو وصلت لورقة فيها مفتاح تاني، لازم تفصلهم: اعمل عقد داخلية لحد أول بت مختلف بين المفتاحين، وحطهم تحت آخر واحدة.

```c
link split(link p, link q, int w)
  { link t = NEW(NULLitem);
    switch(digit(p, w)*2 + digit(q, w))
      {
        case 0: t->l = split(p, q, w+1); break;
        case 1: t->l = p; t->r = q; break;
        case 2: t->r = p; t->l = q; break;
        case 3: t->r = split(p, q, w+1); break;
      }
    return t; }
link insertR(link h, Item item, int w)
  { Key v = key(item);
    if (h == z) return NEW(item);
    if (leaf(h)) return split(NEW(item), h, w);
    if (digit(v, w) == 0)
         h->l = insertR(h->l, item, w+1);
    else h->r = insertR(h->r, item, w+1);
    return h; }
```

::figure trie-insert

اتفرّج على الـ stepper: لما N (01110) دخلت وكان فيه I (01001)، الاتنين بيبدأوا بـ 01، فاتعملت عقد داخلية لحد البت التالت اللي بيختلفوا فيه. العقد الداخلية اللي ليها ولد واحد بس دي اسمها **one-way branching**، وهي العيب الأساسي للـ tries — والـ patricia في الدرس الجاي بيشيلها.

### الخصائص

:::problem
شكل الـ trie **مابيعتمدش** على ترتيب الإدخال: فيه trie واحد بس لأي مجموعة مفاتيح مختلفة.
:::

دي خاصية مميّزة جدًا — كل شجر البحث التاني شكلها بيعتمد على الترتيب. والسبب واضح من التعريف: الـ trie متعرّف بالمفاتيح نفسها مش بتاريخ الإدخال. ومن الخاصية دي كمان: الـ trie **مترتب** (الـ inorder على الأوراق = المفاتيح بالترتيب)، فـ sort وselect ممكنين.

:::problem
البحث أو الإضافة لمفتاح عشوائي في trie مبني من N bitstring عشوائي بيحتاج حوالي **lg N** مقارنة بت في المتوسط. وأسوأ حالة محدودة بعدد البتات في المفتاح بس.
:::

:::problem
الـ trie المبني من N مفتاح عشوائي w بت فيه حوالي **N/ln 2 ≈ 1.44N** عقدة (داخلية) في المتوسط.
:::

```
same keys in reverse order give the same trie (Property 15.2): yes
search P -> hit, search Q -> miss

N=   1000 random 31-bit keys: 11.23 bits per search (lg N = 9.97), 2.421 N nodes (1/ln 2 + 1 = 2.443 incl. leaves)
N=  10000 random 31-bit keys: 14.63 bits per search (lg N = 13.29), 2.449 N nodes (1/ln 2 + 1 = 2.443 incl. leaves)
N= 100000 random 31-bit keys: 17.95 bits per search (lg N = 16.61), 2.445 N nodes (1/ln 2 + 1 = 2.443 incl. leaves)
N=1000000 random 31-bit keys: 21.25 bits per search (lg N = 19.93), 2.438 N nodes (1/ln 2 + 1 = 2.443 incl. leaves)
```

الأرقام: البتات لكل بحث = lg N + ثابت صغير (حوالي 1.3). والعقد الكلية ≈ 2.44N: يعني N ورقة + 1.44N عقدة داخلية — بالظبط Property 15.4. يعني الـ trie فيه عقد داخلية أكتر بـ 44% من عدد المفاتيح (BST عادي فيه N عقدة بس). ده تمن الـ one-way branching.

:::oops شرط مهم
الـ tries بتفترض إن مفيش مفتاح **prefix** لمفتاح تاني. لو المفاتيح كلها نفس الطول (أرقام 32 بت)، مضمون. لكن لنصوص بأطوال مختلفة («she» و«shell»)، لازم حل: يا تضيف حرف نهاية مميّز لكل مفتاح، يا تسمح للعقد الداخلية تشيل مفتاح (زي الـ multiway tries في الدرس 37).
:::
